検証の哲学 reference

TENRYU の検証（verification）は、閉じた形の解（closed-form solution）や保存の恒等式（conservation identity）を使う小さな解析的検査（analytic gate）から、固定したデッキ（deck）の基準解（golden）、実行ごとの再現性（reproducibility）、2D RZ（軸対称円筒座標、axisymmetric cylindrical coordinates）の統合試験群（integrated test suite）、コード間ベンチマーク（cross-code benchmark）へと証拠を積み上げる。上位の試験は下位の検査の代用品ではなく、異なる種類の失敗を見つけるための別の正解基準（oracle。結果が正しいかどうかを判定する基準）である。変更によって関連する検査を後退させてはならず、例外は対象と根拠を文書化した場合にかぎり認める。

要点

  • 解析的な検査は、既知の解、独立な積分、保存則、収束次数（order of convergence）と比較し、符号・単位・係数・境界条件の誤りを局所化する。
  • 基準解は、同じ格子と実行条件における変化の検出器であり、正しさや格子収束（grid convergence）の証明ではない。
  • 決定論的（deterministic）な 1D の経路では、同じバイナリ・入力・GPU 構成のもとで、実行ごとにビット単位（bitwise）で一致することが必須である。
  • 2D RZ でも、1 ステップ内で状態や時間刻みに入る浮動小数点の和は固定順（fixed order）で計算し、同じ構成の 2 本の実行にビット単位の一致を要求する。雑音帯（noise band。同じ構成の反復実行のばらつきから較正した、差の許容幅）は、反復実行の差が 0 でない経路にだけ、デッキと指標ごとに用いる。

検証が答える問い

検証が問うのは、「実装した数値解法が、定めた数式と離散化の仕様のとおりに解けているか」である。実験と一致し、現実を十分に表しているかという妥当性確認（validation）は、別の問いである。TENRYU は流体、熱伝導、輻射、レーザーのそれぞれを、既知の解・参照解（reference solution）・収束性で検査し、さらに単位の境界、エネルギー台帳（energy ledger）による保存の検査、モジュール間の連成（coupling）も試験する。とくに、質量不透明度（mass opacity）\(\kappa\) [cm²/g] と長さあたりの不透明度（length opacity）\(\sigma\) [cm⁻¹] の取り違えのように、計算が完走しても物理を大きく誤る失敗を、小さく識別力の高い試験で捕まえる。

基本の構成は単体（unit）・統合（integration）・回帰（regression）の 3 層だが、運用上は 5 種類の検査に分けると役割が明確になる。小さな検査は原因の位置を絞り込み、連成した試験群は、個別には正しい部品が実運用の時間ループ、メッシュ、EOS（equation of state、状態方程式）のクロージャ（closure）、エネルギー台帳のなかでも整合するかを調べる。コード間ベンチマークは独立な実装との傾向の差を示すが、内部の検証や実験による妥当性確認の代わりにはならない。

検査の分類

検査の種類正解の基準と対象代表例
1. 解析解・単体単一の物理カーネル、離散演算子（discrete operator）、保存の恒等式を、閉じた形の解、独立な積分、固有値、文献の解と照合する。Sedov / Noh、Marshak のスペクトル、SNB（Schurtz–Nicolaï–Busquet モデル）の分散関係（dispersion relation）、Beer–Lambert、レーザーの屈折。
2. 基準解との回帰固定したデッキと実行条件の履歴（history）指標を、承認済みの JSON の基準値と、指標ごとの許容差で比較する。verify_gxii_1d_fld_regression の吸収エネルギー、最大圧縮時刻、ピーク密度、面密度 ρR、中心温度。
3. 再現性同じ入力での反復実行、必要に応じて MPI（Message Passing Interface）のランク（rank）数を変えた実行を、ビット単位の一致、縮約順序の帯（reduction-order band。MPI の縮約（reduction）で加算の順序だけが変わるときの、差の許容幅）、雑音帯（反復実行の差が 0 でない経路だけに使う帯）のいずれかの基準で比較する — 検証ページの再現性の検査参照。決定論的な 1D の場と診断量、連成試験群における反復実行と、機能オフの一致（feature-off identity。機能を無効にした実行が、その機能のない経路とビット単位で一致すること）。
4. 統合試験群流体、輻射、材料、メッシュ、境界の台帳を、実運用のループのなかで同時に検査する。CTest の試験群 I1（グレイ（gray）輻射衝撃波）、I2（多群（multigroup）の流束制限拡散（flux-limited diffusion、FLD）のグレイ一致）、I3（SN（離散座標法、discrete ordinates method）の輻射衝撃波を、角度の次数、不透明度の倍率、格子を順に変えて調べる試験群）。タグの意味はタグ凡例参照。
5. コード間ベンチマーク入力の物理的な意味をそろえたうえで、別実装との分布・傾向・吸収量を比較する。HELIOS との 1D のコード間ベンチマーク（照射条件をそろえた LTE（局所熱力学平衡、local thermodynamic equilibrium）の比較）。

この並びは、強さの単純な順位ではない。解析的な検査は狭い範囲で強い正解基準をもち、統合試験群は広い範囲を同時に通す。後者が合格しても、誤差が相殺して単一演算子の符号の誤りを見逃す可能性があるため、前者を削除することはできない。逆に単体試験がすべて合格しても、演算子の順序、古いままの EOS、整合しないメッシュの更新、源の二重注入といった連成に固有の欠陥は、試験群でなければ見えない。

正解基準と許容差の作り方

良い検査は、「実装が誤っていても同じ答えを返してしまう補助関数」を参照側で再利用しない。可能な場合は、実運用の経路から独立した積分、解析的な衝撃波の位置、離散的な固有値、公開されている解を使う。判定に使う量も問題に合わせる。Sedov / Noh では波面の位置、プラトー、保存を、多群 Marshak では独立なプランク積分によるスペクトルを、Beer–Lambert では既知の光学的厚さ（optical depth）を調べる。単に実行が完走することは簡易確認（smoke test）であって、精度の基準ではない。

許容差は、すべての検査に共通する便利な百分率ではなく、正解基準と数値的な雑音の性質から決める。決定論的な減衰の追跡には、厳しい相対誤差を使える。衝撃波を捕捉した分布では、格子誤差と測定に使う推定量（estimator）を考慮する。統計的な手法なら、信頼区間（confidence interval）や粒子数に対する収束を用いる。物理モデルとしての帯と、離散演算子の精度も分ける。モデルの既知の限界を、帯を広げることで「検証済み」に見せてはいけない。

基準解と、その取り直し

GXII（激光 XII 号、GEKKO XII。検証ページで定義するベンチマーク）の 1D FLD の基準解は、レーザーの沈着、流体、熱伝導、2 温度の物質、FLD を通る実運用の軌道に対する回帰試験である。最終ファイルのバイト比較ではなく、実行終了時の累積値である吸収したレーザーエネルギーと、履歴の時系列から取り出した最大圧縮時刻、rho_peak_max、面密度 rhoR_max、中心温度 Tc_max_eV を、それぞれの許容差で比較する。run_profile（格子や実行時間などの実行条件を記録した文字列）が違えば比較を失敗させるため、短縮した実行や別の格子を同じ基準値に見せかけることはできない。

基準解は、同じ格子・同じ実行条件に対する変化の検出器である。そこに一致したからといって、解析的な正しさも格子収束も証明されない。取り直し（re-baselining）が許されるのは、既知の不具合の修正、物理アルゴリズムや基準となるパラメータの意図的な変更、あるいはコードの責任者が承認した明示的な理由がある場合である。更新には、理由、旧値と新値の定量的な差、複数解像度での収束データ、レビューが必要である。単に現在の実行が失敗しているから、あるいは新しい値へ合わせれば CI（continuous integration、継続的インテグレーション）が通るから、というのは理由にならない。許容差の緩和も同じ基準で扱う。

再現性の要求

決定論的な 1D の経路では、同じバイナリ、デッキ、GPU 構成による反復実行のあいだで、場と主要な診断量がビット単位で一致しなければならない。物理的な検査が数 % の許容差をもっていても、その幅を同じ構成での実行ごとのずれに流用することはしない。1D のレーザー沈着における専用領域への蓄積と固定順序の総和のように、加算の順序を固定することもアルゴリズムの仕様の一部である。目標値に近い 2 本の実行ではなく、同じ数値の軌道を要求する。

2D RZ でも、1 ステップの中で状態や時間刻みに入る浮動小数点の和は、加算の順序がスレッドの実行順に依らないように固定順で計算する。節点やセルへの和は、対象 1 つにつき 1 スレッドが接続表のキーの昇順に足し、レーザーの沈着は 128 ビット固定小数点の整数の和を 1 回だけ丸める。このため 2D RZ でも、同じ構成の 2 本の実行にビット単位の一致を要求する。一致しないことは、固定順になっていない和、またはほかの非決定性が残っている印である。雑音帯は、反復実行の差が 0 でない経路にだけ、同じ構成での反復実行から自己較正した帯、または複数本の実行（アンサンブル、ensemble）から較正して固定した帯を、デッキと指標を指定して使う基準であり、2D 全体に対する包括的な許容差ではない。決定論的な中間量、1D の経路、雑音と無関係な量は、ビット単位の一致か、本来の厳しい検査のままである。

変更を受け入れる条件

物理、数値解法、並列の縮約（parallel reduction）、出力する指標の変更は、影響する既存の検査に合格したうえで、新しく保証する事項に対応する検査を、既存の分類の適切な種類へ加える必要がある。解析的な検査の後退を、統合結果の改善で相殺したり、基準解の更新で隠したりしてはいけない。例外が必要なら、対象となる試験、指標、構成、物理的または数値的な根拠、代替となる正解基準、期限つきか恒久的かの区別を文書化する。スキップは合格ではない。環境依存で実行されなかった場合は、その状態とログを残す。

この方針の目的は変更を止めることではなく、何が変わり、どの証拠がそれを支え、どの保証が残っているかを明確にすることである。解析解、基準解、再現性、試験群、コード間ベンチマークのすべてが同じ答えを出す必要はない。それぞれが自分の担当する失敗の種類を監視し、変更後もその保証を後退させないことが、TENRYU の検証における判定基準である。
