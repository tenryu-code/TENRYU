namelist reference

このページは、デッキ（deck。TENRYU の入力となる 1 個の Python ファイル）に書く namelist の全キーを列挙する仕様書ではなく、目的の設定へたどり着くための案内図である。最上位のブロック、主要な下位ブロック、代表的なキーの関係を示す。キーの完全な仕様 — 型、単位、許容値、組合せの制約、正典となる既定値の一覧 — は、ソースとともに配布される仕様書、すなわち TENRYU リポジトリ（コードと同様に公開されている）の docs/SPECIFICATION.md の §6.4（スキーマ）と §9.1（既定値）にある。デッキ、namelist、ブロック、下位ブロック、キーの定義は用語の節にある。

要点

  • ブロックは 11 個あり、Main から Parallel までが、ケースの識別、メッシュ、物性、初期条件、物理、数値解法、出力を分担する。
  • キーの値が辞書（dict）のものは、独自のキーの集合をもつ下位ブロックである。たとえば Numerics.dt.max_s と Numerics.hydro.av_C2 は、別々の下位ブロック dt と hydro のキーで、受け付ける値の検査が別である。
  • 未知のキー、型の違い、範囲外の値、対応していないブロックの組合せは、いずれも入力エラーである。打ち間違いが黙って既定値に戻ることはない。例外は、互換のために受理して WARNING を出し、何もしないキーが少数あることである（検証と既定値）。
  • 以下のキーは入口を示す例であり、完全な一覧ではない。このページの表は意図的に既定値を載せていない。各カーネルページには主要な既定値が載っており、それが SPECIFICATION §9.1 と食い違う場合は §9.1 が正である。

この計算で使う用語

このページと、このページへリンクするページは、デッキ、namelist、ブロック、下位ブロック、キーの 5 つの語を、次の意味で使う。

デッキと namelist

デッキ（deck）は、TENRYU に渡す入力の、1 個の Python ファイルである。tenryu run deck.py や tenryu validate deck.py の引数がデッキで、1 回の計算のすべての条件 — メッシュ、材料、初期条件、物理、数値解法、出力 — をこのファイル 1 つに書く。デッキは通常の Python のスクリプトとして実行されるので、関数や定数を自由に定義でき、環境変数も読める。TENRYU は、デッキを組み込みの Python インタプリタで 1 回だけ実行する。デッキが呼んだブロック関数は、その場でキーの名前と値を検査して登録し、実行が終わったあとに、TENRYU がブロックをまたぐ検査をして設定を確定する。リポジトリの docs/SPECIFICATION.md §6 は、このファイルを namelist と呼ぶ。

namelistは、デッキの書式の名前である。書式は、tenryu_namelist モジュールが提供するブロック関数と、その関数が受け付けるキーの体系で定まる。このモジュールは TENRYU の実行ファイルに組み込まれていて、デッキは先頭で from tenryu_namelist import * と書いてブロック関数を使う。このサイトでは、ファイルをデッキ、書式を namelist と呼び分ける。このページは、namelist のキーの案内である。

ブロックと下位ブロック

ブロック（block）は、デッキの最上位の設定の単位で、同名の Python の関数（ブロック関数）として呼ぶ。Main、Mesh、Materials、Geometry、Radiation、Laser、Numerics、Output、Diagnostics、Parallel、Burn の 11 個がある。ブロック関数は、キーワード引数（キー = 値）で設定を受け取り、値を TENRYU に登録するだけで、戻り値を使わない。

Main・Mesh・Materials・Geometry は必須で、欠けるとデッキの検査が Required block not provided で止まる。ほかのブロックは省略でき、省略したブロックのキーはすべて既定値になる。たとえば Radiation.enabled の既定は True なので、輻射を使わないデッキは Radiation(enabled=False) と書く。各ブロックは 1 回だけ呼ぶ。2 回呼ぶと WARNING が出て、後の呼び出しが前の値を上書きする。

Material(...) と LaserBeam(...) はブロックではなく、辞書（dict）を返す補助の関数である。Material の辞書は Materials(materials=[...]) のリストに、LaserBeam の辞書は Laser.beams のリストに入れる。

下位ブロック（sub-block）は、ブロックのキーの値として書く辞書（dict）のうち、それ自身が受け付けるキーの集合をもつものである。Numerics の dt=dict(max_s=…, min_s=…) がその例で、Numerics.dt と呼ぶ。下位ブロックの中に、さらに下位ブロックが入ることもある（Numerics.ale.band_ale）。Material(...) や LaserBeam(...) が返す辞書も、リストの要素として渡す下位ブロックである。

キー

キー（key）は、ブロックまたは下位ブロックに渡す設定項目の名前である。ブロック関数のキーワード引数の名前（Main(t_end=…) の t_end）と、下位ブロックの辞書のキーの名前（dt=dict(max_s=…) の max_s）が、どちらもキーである。同じ名前のキーが複数のブロックにあるので（enabled など）、キーは、ブロック名と下位ブロック名を . でつないだ完全修飾名（fully qualified name、Numerics.conduction.enabled）で呼ぶ。キーの名前は、そのブロックまたは下位ブロックが受け付ける名前の集合と照合され、集合にない名前は入力の誤りになる（検証と既定値）。

ブロックの地図

デッキでは通常、from tenryu_namelist import * のあと、各ブロック関数を 1 回ずつ呼ぶ。材料は、辞書を返す Material(...) を作って Materials(materials=[...]) に登録し、レーザーのビームは、同じく辞書を返す LaserBeam(...) を Laser.beams へ渡す。表の「代表的なキー」は探し始める起点である。詳細な入れ子のスキーマや、モードごとの排他条件は仕様書の側にある。

キーの読み方

完全修飾名（キー）で考えると、似た名前を取り違えにくくなる。たとえば enabled は多くのブロックにあるが、Radiation.enabled、Numerics.conduction.enabled、Burn.enabled はそれぞれ別のスイッチである。同様に、輻射の境界には、選んだソルバごとの下位ブロックに置くものと、最上位の Radiation.boundary に置くものがある。名前だけから入れ子の位置を推測せず、§6.4 の該当ブロックを確認すること。

値には cgs + eV の単位系を使う。長さは cm、時間は s、密度は g/cm³、温度と光子群の境界は eV である。ただし wavelength_nm や T_floor_keV のように名前が単位を明示しているキーでは、その接尾辞が単位を定める。単位、型、次元ごとの制約は代表的なキーの表からは省いてあるため、実際の値を入力する前に仕様書の個別の記述を読む必要がある。

検証と既定値

パーサは各階層で、既知のキーかどうかを検証する。未知のキーを捨てて続行することはせず、誤った型、必須の値の欠落、範囲の違反、相互に排他的なモード、次元や MPI のランク数に対して対応していない設定があれば、入力の誤りとして停止する。誤りは、例外 ConfigError または ValueError として報告され、どちらも先頭が TENRYU ERROR [namelist]: の行で表示される。この検査は、設定の打ち間違いが、原因の分からない物理結果として後から現れるのを防ぐ。

例外は、互換のために受理するだけで何もしないキーである。受理すると、そのキーが何もしないことを知らせる WARNING が出る。たとえば、Numerics.dt.f_min_fleck と Numerics.safety.opacity_floor・opacity_cap は、現在のビルドに含まれないモンテカルロ輻射のキーである。Diagnostics.shell も何もしない（殻の診断は Numerics.diagnostics.icf が行う）。

正典となる完全なリファレンス

このページは案内図である。完全なキーのリファレンスは TENRYU リポジトリ（ソースとともに配布される公開文書）の docs/SPECIFICATION.md §6.4、既定値の正典となる一覧は同 §9.1 である。本サイトの各カーネルページに載る既定値は、フッタに示すドキュメント日付の時点で正確である。サイトと §9.1 が食い違う場合は §9.1 が優先される。新しいデッキを作るとき、モードを変えるとき、既定値に依存した解釈をするとき、検証のエラーを解消するときは、この仕様書を確認すること。
