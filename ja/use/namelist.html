namelist リファレンス reference

このページは Python の namelist の全キーを列挙する仕様書ではなく、目的の設定へたどり着くための案内図である。最上位のブロック、主要な下位ブロック、代表的なキーの関係を示す。完全なキーの表面 — 型、単位、許容値、組合せの制約、正典となる既定値の一覧 — は、ソースとともに配布される仕様書が保持する：TENRYU リポジトリ（コードと同様に公開されている）の docs/SPECIFICATION.md §6.4（スキーマ）と §9.1（既定値）である。

要点

  • Main から Parallel までのブロックが、ケースの識別、メッシュ、物性、初期条件、物理、数値解法、出力を分担する。
  • 括弧内の dict は、独立したスキーマをもつ下位ブロックである。たとえば Numerics.dt.max_s と Numerics.hydro.av_C2 は別々の契約である。
  • 未知のキー、型の違い、範囲外の値、対応していないブロックの組合せは、いずれも入力エラーである。打ち間違いが黙って既定値に戻ることはない。
  • 以下のキーは入口を示す例であり、完全な一覧ではない。このページの表は意図的に既定値を載せていない。各カーネルページには主要な既定値が載っており、両者が食い違う場合は SPECIFICATION §9.1 が正である。

ブロックの地図

デッキでは通常、from tenryu_namelist import * のあと、各コンストラクタを 1 回ずつ呼ぶ。材料は Material(...) を作って Materials(materials=[...]) に登録し、レーザーのビームは LaserBeam(...) を Laser.beams へ渡す。表の「代表的なキー」は探し始める起点である。詳細な入れ子のスキーマや、モードごとの排他条件は仕様書の側にある。

キーの読み方

完全修飾名で考えると、似た名前を取り違えにくくなる。たとえば enabled は多くのブロックにあるが、Radiation.enabled、Numerics.conduction.enabled、Burn.enabled はそれぞれ別のスイッチである。同様に、輻射の境界には、選んだソルバごとの下位ブロックに置くものと、最上位の Radiation.boundary に置くものがある。名前だけから入れ子の位置を推測せず、§6.4 の該当ブロックを確認すること。

値には cgs + eV の単位系を使う。長さは cm、時間は s、密度は g/cm³、温度と光子群の境界は eV である。ただし wavelength_nm や T_floor_keV のように名前が単位を明示しているキーでは、その接尾辞が契約になる。単位、型、次元ごとの制約は代表的なキーの表からは省いてあるため、実際の値を入力する前に仕様書の個別の記述を読む必要がある。

検証と既定値

パーサは各階層で、既知のキーかどうかを検証する。未知のキーを捨てて続行することはせず、誤った型、必須の値の欠落、範囲の違反、相互に排他的なモード、次元や MPI のランク数に対して対応していない設定を、ConfigError として停止させる。この挙動は、設定の打ち間違いを物理結果の違いとして後から発見する事態を避けるための、入力の契約である。

正典となる完全なリファレンス

このページは案内図である。完全なキーのリファレンスは TENRYU リポジトリ（ソースとともに配布される公開文書）の docs/SPECIFICATION.md §6.4、既定値の正典となる一覧は同 §9.1 である。本サイトの各カーネルページに載る既定値は、フッタに示すドキュメント日付の時点で正確なものである。サイトと §9.1 が食い違う場合は §9.1 が優先される。新しいデッキを作るとき、モードを変えるとき、既定値に依存した解釈をするとき、検証のエラーを解消するときは、この仕様書を確認すること。
