出力と解析 reference

TENRYU の 1 回の実行は、スナップショット（空間場）・履歴（history。スカラー時系列）・チェックポイント（再開（restart）用）の 3 種の HDF5 と、来歴（provenance）のファイル（凍結設定（frozen configuration）・実行情報・ログ）を生成する。このページは何が出力されるかを一覧にする — ファイルの種類と命名、スナップショットのグループと主なデータセット、履歴の主なチャネル、チェックポイントの追加内容、そして読み方。データ型・配列形状まで含む正典はリポジトリの docs/SPECIFICATION.md §7（要約は docs/OUTPUT_SCHEMA.md）である。この出力の読み方に固有の用語は用語の節で説明する。

要点

  • 3 種の HDF5: スナップショット <name>_NNNN.h5、履歴 <name>_history.h5（追記型）、チェックポイント <name>_ckpt_NNNN.h5。出力間隔は「N ステップごと」（plot_every 等）と「T 秒ごと」（plot_every_s 等）の OR で発火する。
  • 全数値データセットに units 属性が付く。mesh/・hydro/ のデータセット名は内部の State フィールド名と 1:1 対応する。
  • 爆縮（implosion）の停滞期（stagnation phase）のピークは短い — 2026-07-31 の GXII（激光 XII 号、GEKKO XII）級のレーザー爆縮の計算では約 15 ps — ため、ピーク値はスナップショットではなくステップごとの履歴（implosion/*）から読む。
  • 同じ出力ディレクトリへ再実行すると、上書きせず _001 のような連番ディレクトリに書かれる。「結果が変わらない」と思ったらまず出力先を確認する。

ファイル構成・命名・出力間隔

ファイル命名出力頻度用途
スナップショット<name>_NNNN.h5（4 桁ゼロ詰めの通し番号）plot_every ステップごと または plot_every_s 秒ごと（OR 論理）場の可視化・後処理。物理時刻はルート属性 t、ステップ番号は step（同じ値を cycle にも書く）。
履歴<name>_history.h5history_every / history_every_s（OR、追記）スカラー診断量の時系列。拡張可能なデータセット（extensible dataset）に出力のたびに追記する。
チェックポイント<name>_ckpt_NNNN.h5（4 桁ゼロ詰めの通し番号）checkpoint_every / checkpoint_every_s（OR）再開用。checkpoint_keep_last 個だけ保持し、古いものは自動削除する。

<name> は Main.name、未指定ならデッキ（deck。定義）のファイル名（拡張子なし）である。MPI（message passing interface）並列の run でも、スナップショット・履歴・チェックポイントはすべてランク 0（MPI のプロセス番号 0）が書き、ランクごとのファイルは作らない。ディレクトリ全体の配置は次のとおりである。

outputs/<name>/
├── results/                  ← スナップショットと履歴
│   ├── <name>_0000.h5
│   ├── <name>_0001.h5
│   └── <name>_history.h5
├── config/                   ← 来歴（凍結設定とデッキの写し）
│   ├── <name>_frozen.json
│   └── <name>_namelist.py
├── checkpoints/              ← 再開用
│   └── <name>_ckpt_0000.h5
├── log/                      ← 実行ログ（tenryu.log）
├── run_info.json             ← 実行の要約（終了状態など）
└── mesh_requirement.json     ← 初期メッシュの分解能要求の判定（1D の新規 run のみ）

スナップショットとチェックポイントのファイル名の番号は、その出力ディレクトリへ書き出した順に 0 から数える通し番号であり、ステップ番号ではない。たとえば 100 ステップごとにチェックポイントを書く run の最初のチェックポイントは <name>_ckpt_0000.h5 である。ステップ番号はルート属性 step（同じ値を cycle にも書く）にある。出力ディレクトリに stop_request というファイルを置いて run を止めたときは、通し番号の代わりにステップ番号を付けた event_stop_<ステップ番号>.h5 を checkpoints/ に書く。このファイルは checkpoint_keep_last による自動削除の対象にならない。

mesh_requirement.json は、1D の新規 run だけが書く。初期メッシュが、物理から要る分解能を満たすかどうかの見積もりと判定の記録である。対象外のとき（レーザーが無効など）は applicable が false になり、理由を reason に記す。

出力先が既に存在して衝突する場合は、上書きせず outputs/<name>_001/ のような 3 桁連番の別ディレクトリへ書く。デッキを編集せずに出力先を変えたいときは tenryu run <deck> --output-dir <dir> で実行時に上書きできる（新規 run 専用。再開との併用は ConfigError）。

この計算で使う用語

出力の読み方に固有の用語を、以下で定義する。エネルギー台帳（energy ledger）の人工項、来歴と凍結設定、シェルの半径・厚さ・IFAR・収束比、ホットスポットのガスとその半径である。Δt を決めた制約（履歴の dt_winner などの「勝者」）は、時間刻み制御で定義する。

エネルギー台帳と人工項

エネルギー台帳は、毎ステップ、系の全エネルギーの変化を、出入りと補正の各項と突き合わせる恒等式である。履歴の energy/ の各チャネルがその項を持ち、conservation_error がその相対誤差 ε_budget である。恒等式と各項の定義は数値基盤のエネルギー台帳の節にある。以下は、数値的な操作が状態へ加えたエネルギーを記帳する 4 項である。

床補正（floor correction）は、各演算子がエネルギーそのものを下限まで引き上げた量の和である（床・クランプ・安全ガード）。floor_injected が run 全体の累積、floor_injected_step がそのステップの値である。

安全補正（safety correction）は、伝導の安全補正を記帳する欄である。現在の実装は伝導の補正を床補正に含めて記帳し、この欄に床補正と同じ値を入れるので、safety_injected は floor_injected と同じ値になる。

ALE 再分配の未解決分（unresolved ALE redistribution）は、2D RZ の ALE（arbitrary Lagrangian–Eulerian、任意ラグランジュ・オイラー法）のリマップが、質量の床に落ちたセルを床の状態に置いたときのエネルギー差と、運動エネルギー・クロージャの再配分（Numerics.ale.ke_closure_redistribute_floor、既定は False）が吸収しきれなかった不足の和である。ALE を使わなければ 0 である。redistribution_unresolved には、そのステップの値だけを書く。

ソルバ残差（solver residual）は、陰的ソルバの残差を符号つきで記帳する欄である。どの演算子も加算しないので、solver_residual は常に 0 である。0 以外の値は、符号に応じて流入または流出の項になる。

保存誤差 ε_budget の計算では、床補正と ALE 再分配の未解決分の和を人工項として全エネルギー変化から差し引く（安全補正は床補正と同じ値なので、加えない）。人工項は、物理的な出入りではなく数値的な操作がもたらしたエネルギーなので、ε_budget には数えない。ε_budget は Diagnostics.energy_budget.warn_threshold（既定 \(10^{-3}\)）を超えると警告する（最初のステップは検査しない）。床補正・安全補正・ALE 再分配の未解決分は、それぞれステップ開始時のエネルギーの大きさ E_denom との比が \(10^{-3}\) を超えると警告する。ε_budget が跳ねたときは、まず人工項の比を見る。人工項が支配的なら床とクランプの発動源を、そうでなければ境界と源の帰属（吸収率・逸出）を疑う。

来歴と凍結設定

来歴（provenance）は、ある出力がどの入力とどの実行環境から生まれたかを、後から確かめるための記録である。TENRYU は、デッキの写し config/<name>_namelist.py（Output.save_namelist_copy、既定は True）、凍結設定の JSON config/<name>_frozen.json（Output.save_frozen_config、既定は True）、実行の要約 run_info.json、実行ログ log/tenryu.log、各 HDF5 の metadata/ グループ（デッキ全文 namelist_source、凍結設定 frozen_config、輻射群の境界 group_bounds_eV など）を来歴として残す。「入力したつもりの値」ではなく、実行が実際に受け取った構成を監査する一次資料である。各ファイルの中身は来歴の節に書く。再開が元の run の厳密な継続でないときは、ルート属性 restart_provenance にその印を書き、再開した run の出力を継続した run の出力と区別できるようにする。グループ名に provenance を含む diagnostics/ale_provenance/v1/ は別の記録で、ALE の設定が標準のプロファイルに沿っていたかを記す（履歴の節の表）。

凍結設定（frozen configuration）は、初期化時に Python の関数を表にし、既定値を補って確定した設定である。定義は実行ページにある。来歴の凍結設定は、解決した設定の全体と実行時の値の要約を持つ config/<name>_frozen.json と、再開時の照合に使う HDF5 の metadata/frozen_config の 2 つの形で残る。HDF5 の属性 git_hash は常に "unknown" なので、HDF5 からは実行したコミットが分からない。config/<name>_frozen.json の _tenryu_version は、公開版の番号である。

シェルの半径・厚さ・IFAR・収束比

シェル（shell）は、爆縮するカプセルの高密度の殻である。履歴の diagnostics/icf/v1/ は、密度の分布からシェルの位置と形を次の規則で測る。1D の規則を述べる。\(\rho_{peak}\) は全セルの密度の最大値である。

シェル半径（shell radius） \(R_{shell}\)（shell_radius_cm）は、\(\rho\ge0.1\rho_{peak}\) のセルについて、セル中心の半径（両側の節点の半径の平均）を質量で重み付けして平均した値である。

シェルの厚さ（shell thickness） \(\Delta R_{shell}=R_{outer}-R_{inner}\)（shell_thickness_cm）の \(R_{outer}\) は、密度が外側のしきい値以上のセルのうち最も外側のセルの、外側の節点の半径である。\(R_{inner}\) は、密度が内側のしきい値以上のセルのうち最も内側のセルの、内側の節点の半径である。しきい値は Numerics.diagnostics.icf.rho_outer_threshold_g_per_cc と rho_inner_threshold_g_per_cc で指定する。0（既定）なら、外側は \(\rho_{peak}\) の 0.1 倍、内側は 0.5 倍になる。

IFAR（in-flight aspect ratio、飛行中のアスペクト比） \(\mathrm{IFAR}=R_{shell}/\Delta R_{shell}\)（IFAR）は、殻が薄いほど大きい。

収束比（convergence ratio、CR） \(\mathrm{CR}=R_{initial}/R_{shell}\)（CR）の \(R_{initial}\) は、シェルを有効に測れた最初のステップのシェル半径で、履歴の diagnostics/icf/v1/ の属性 R_initial_cm に書く。CR の最初の値は 1 であり、殻が縮むほど大きくなる。再開した run は、再開元の run の履歴ファイルから \(R_{initial}\) を読み戻す。

2D の構造格子では、\(R_{shell}\) の重みの半径にセルの r 座標（両側の節点の r の平均）を使い、\(R_{outer}\) と \(R_{inner}\) は赤道面（\(z=0\)）で r を 0 から外縁まで 1024 区間に分けた線上の密度から求める（\(R_{inner}\) は、中心側から見て密度が内側のしきい値を最初に越える点を線形補間する）。履歴の implosion/shell_radius_mean は、同じ \(\rho\ge0.1\rho_{peak}\) のセルについて、セル重心の半径を質量で重み付けして平均する。両者の値は、重心と中点の違いのぶんだけ異なる。

ホットスポットのガスと R50…R99

ホットスポットのガス（hotspot gas）は、初期に標的の中心部にあったガスを、流れとともに運ぶ受動トレーサで印を付けたものである。Numerics.diagnostics.hotspot_gas.enabled=True にすると、ステップ 0 で、セル重心の中心からの距離 \(\sqrt{r^2+z^2}\)（1D は \(r\)）が Numerics.diagnostics.hotspot_gas.R_g_cm（\(R_g\) [cm]。有効なら 0 より大きくする）より小さいセルにトレーサ \(Y_g=1\) を付け、ほかのセルは 0 とする。トレーサは、ラグランジュ流体ではセルとともに動き、ALE のリマップでは質量 \(mY_g\) を流体の質量流束と同じ風上の規則と制限子で運ぶ。値は hydro/gas_tracer_Y に残る。印を付けた最初の質量が gas_mass_initial_g、各時刻の質量 \(M_g=\sum_c m_cY_{g,c}\) の初期値との相対差が gas_mass_rel_drift で、その絶対値が Numerics.diagnostics.hotspot_gas.mass_drift_warn_rel（既定 \(10^{-10}\)）を超えると警告する。

ガスの半径 R50・R90・R95・R99 は、ガスの質量で重み付けした半径の分位数である。トレーサを持つセルをセル重心の中心からの距離で昇順に並べ、質量 \(mY_g\) の累積が \(M_g\) の p %（p = 50・90・95・99）に最初に達するセルの距離を、それぞれ \(R_{p}\)（R50_cm・R90_cm・R95_cm・R99_cm）とする。ガスの収束比 \(\mathrm{CR}_{p}=R_g/R_{p}\)（CR50・CR90・CR95・CR99）は、初期の半径 \(R_g\) を現在の半径で割った量である。シェルの収束比 CR とは別の量である。\(\mathrm{CR}_{50}\) の初期値は 1 でない（密度が一様な球では \(2^{1/3}\simeq1.26\)）ので、その初期値で割った C_R50_norm も書く。

そのほかの量を次のように定義する。rms 半径 \(R_{rms}=\sqrt{(5/3)\langle r^2\rangle}\)（Rrms_cm。一様な球では球の半径に等しい）とその収束比 CRrms。ガスの体積平均密度 \(M_g/\sum_c Y_{g,c}V_c\)（rho_bar_volume_gcc）の初期値に対する比の 1/3 乗 CR_V。ガスの質量中央値の密度 rho50_gcc の初期値に対する比の 1/3 乗 CR_rho50。圧力 \(p\)（電子 + イオン）と、断熱線を表す量 \(K=p/\rho^{\gamma}\)（K_mean・K50・K90・K95・K99。\(\gamma\) は最初のボイドでない理想気体材料の断熱指数で、定義できなければ 5/3）の質量重みの平均と分位数。電子温度とイオン温度（イオン温度は 2 温度のときだけ）の質量重みの平均と p10・p50・p90。エネルギー（内部・運動・合計）と、その初期値からの変化である仕事プロキシ（work proxy）hotspot_work_proxy_*_erg。仕事プロキシは、トレーサで定義した領域の全エネルギー \(\sum_c Y_gm(e_e+e_i+\tfrac12|\mathbf{u}|^2)\) の変化であり、境界の圧力仕事の積分ではない（hotspot_work_definition に同じ定義を書く）。

スナップショットのデータセット

ルート属性は t（時刻 [s]）、dt（Δt [s]）、cycle と step（どちらもステップ番号）、geometry（"1D_SPH"|"2D_RZ"）、nr・nz（Mesh.nr と、2D の Mesh.nz。1D の nz は 1）、n_cells、n_nodes、n_groups、n_materials、two_temperature（常に 1）、schema_version である。再開が元の run の厳密な継続でないとき（たとえば、Numerics.ale.band_ale の状態を保存した補助ファイル、すなわちチェックポイントの名前に .band-state を付けたファイルが無いチェックポイントから再開したとき）は、その印を文字列のルート属性 restart_provenance（例: RESTART_WITHOUT_BAND_STATE）に書く。geometry は 1D では平面・円筒でも "1D_SPH" なので、1D のファイルは座標系を表す geometry_1d（"spherical"|"cylindrical"|"planar"）も持つ。1D では配列は 1 次元フラット、mesh/x_z・v_z は省略される。以下、グループごとに列挙する（「optional」は生成条件付き）。

警告: 出力間隔によるピークの取り逃がし

スナップショットの出力間隔はデッキごとに設定するが、爆縮の停滞期のピークは非常に短いことがある — GXII 級のレーザー爆縮の計算での実測（2026-07-31）では約 15 ps。出力の時刻がピークの前後に来てしまうと、スナップショット中の最大密度は真のピークを大きく過小評価する。鋭いピークの値とその時刻はステップごとの履歴にある implosion/rho_peak から読み、スナップショットはピーク前後の空間構造を調べるために使うこと。

burn_state/specific_inventory核燃焼の比インベントリ（specific inventory）\(Y_s\) [1/g]（セルごとに D・T・He3・He4・p の順）。再開は、スナップショットの数密度 hydro/burn_n_* を密度で割った値ではなくこれを使う（2026-09-26 から）。
radiation_sn/（1D SN）線形不連続法の角度分布（psi_prev・psi_sd_prev）とセル内の電子エネルギーの差（ee_node_offset）。無いチェックポイントからは等方・一様で始める。
particles/・rng/schema 1 のチェックポイントだけが持つ。particles/ は退役したモンテカルロ輻射の粒子プールで、空なら読み、粒子があれば再開を拒否する。rng/ は乱数状態で、再開では読まない。schema 2（2026-09-29）ではどちらも書かない。

再開の互換規約: schema_version（現行は 2026-09-29 からの 2）が現行と同じなら通常読込、古い（または欠落）なら不足項目を既定値で補う後方互換読込、新しいなら読込拒否。チェックポイントの凍結設定（デッキ本文のハッシュと、Main.restart_from を除くすべての設定）が再開に使うデッキと一致しなければ、再開は拒否される。再開の指定方法は実行ページを参照のこと。

来歴: 凍結設定の JSON・run_info・ログ

config/<name>_frozen.json は、既定値を解決した設定の全体（main・mesh・materials・laser・numerics などの節。Python の関数は name・repr・source_hash（ソースコードのハッシュ）で記す）に、TENRYU のバージョン _tenryu_version、凍結した UTC 時刻 _frozen_at、デッキ本文のハッシュ _namelist_source_hash、frozen_summary を加えた JSON である。frozen_summary には、初期の密度（最小・最大・平均）、電子温度とイオン温度（最小・最大）、材料ごとの体積、および初期化時に表へ変換した関数ごとの時間の範囲（t_min・t_max）・点数 n_points・最大値 peak_value・積分値 integrated_value が入る。HDF5 の metadata/frozen_config は、同じ設定から _tenryu_version・_frozen_at・frozen_summary を除いた JSON である。--output-dir（新規 run）や --t-end・--max-steps（再開）で上書きした値は、config/<name>_frozen.json には実際に使った値が入り、metadata/frozen_config にはデッキの値が残る。「入力したつもりの値」ではなく実行が実際に受け取った構成を監査する一次資料であり、再現・比較の際はデッキとともに保管する。run_info.json は実行の要約、log/ には実行ログが残る。「設定が効いたか怪しい」ときは、凍結設定の JSON → ログの warning の順に見るのが早い。

読み方: CLI・付属ツール・Scope

構造の確認は HDF5 標準ツールで足りる。

h5ls  outputs/<name>/results/<name>_0010.h5          # グループ一覧
h5dump -H outputs/<name>/results/<name>_history.h5  # ヘッダ構造

最短の可視化は付属の tenryu_plot（tools/）である。サブコマンドに profile（空間プロファイル）・history（時系列）・spacetime・summary・compare・spectrum などがある。

python3 -m tools.tenryu_plot --help                  # 一覧
python3 -m tools.tenryu_plot profile outputs/<name>  # 空間プロファイル
python3 -m tools.tenryu_plot history outputs/<name>  # 時系列

Python で直接読むなら h5py が最短である。全数値データセットに units 属性が付き、配列長は場の配置（セル数・節点数・セル×材料・セル×輻射群）に応じて変わるため、ルート属性・形状・単位を合わせて読み取ること。

import h5py
f = h5py.File("outputs/<name>/results/<name>_0010.h5")
Te = f["hydro/Te"][:]; r = f["mesh/x_r"][:]
print(f["hydro/Te"].attrs["units"])   # -> "eV"

対話的な探索と実行どうしの比較には TENRYU Scope（アーキテクチャ参照）を使う。ビューアで着目すべき時刻と量を見つけ、最終的な図は凍結設定と明示したスクリプト引数から作ると、対話的な解析と再現性を両立できる。
