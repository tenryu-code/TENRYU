動作環境と要求スペック reference

TENRYU は NVIDIA CUDA 専用の GPU コードである。このページは、ビルドと実行に必要なマシン・GPU・コンパイラ・ライブラリの要求を一箇所にまとめる。ビルドのページは手順を、本ページは「その手順が成立する環境の条件」を扱う。

要点

  • 必須: NVIDIA GPU + CUDA Toolkit 12.x（12.0 以上）、C++20 コンパイラ（GCC 12+ / Clang 15+）、CMake 3.25+、Ninja、Python 3.10+（開発ヘッダ含む）。
  • 既定ビルドの CUDA アーキテクチャは 70;80;89;90（Volta/Ampere/Ada/Hopper の fatbin）。継続的に検証している実機は A100（40/80 GB）・RTX 4090・RTX 3090 である。
  • MPI と Hypre は opt-in（既定 OFF）。HDF5 と Python は既定 ON。テスト・ログ系の小依存（Catch2/spdlog/CLI11/pybind11）は未導入なら CMake 構成時に自動取得される — オフライン環境では事前導入が要る。
  • 開発・検証の実績はすべて Linux x86_64 上である。他 OS は未検証。

プラットフォームと GPU

対応バックエンドは NVIDIA CUDA のみである（HIP 等の他バックエンドは設計上の非対象）。GPU がなければビルドはできても実行はできない。基本の実行形態は 1 プロセス = 1 GPU で、単一 GPU なら MPI なしで動く。複数 GPU は MPI ビルド（後述）で 1 ランク = 1 GPU として使う。

項目要求 / 既定備考
GPU ベンダNVIDIA のみCUDA 専用。他ベンダ GPU・CPU 単独実行は非対応。
GPU アーキテクチャ既定 fatbin: 70;80;89;90CMAKE_CUDA_ARCHITECTURES で変更可。理論上の下限は倍精度 atomicAdd が要る compute capability 6.0+（ARCHITECTURE §2.2）。sm_86（RTX 30 系）は sm_80 バイナリの前方互換で動く。
検証済みの実機A100 40/80 GB、RTX 4090（24 GB）、RTX 3090（24 GB）回帰・ベンチマークを継続実行している構成。VRAM の必要量は格子規模に依存する — 1D の基準問題は小さく、大規模 2D ほど要る。
OSLinux x86_64（実績）開発・CI 相当の検証・本番実行はすべて Linux。他 OS は未検証。
GPU ドライバCUDA 12.x 対応版nvidia-smi が表示する CUDA Version が 12.x 以上であること。

ツールチェーンとライブラリ

最低バージョンの正典はリポジトリの docs/ARCHITECTURE.md §2.2 である。要求は「必須」「既定 ON（外せるが通常は使う）」「opt-in」の三層に分かれる。

依存最低バージョン層役割・注意
CUDA Toolkit12.0+必須nvcc・ランタイム・cuSPARSE。cuRAND device API（Philox4x32-10）と NVTX はツールキット同梱でリンク不要。
C++ コンパイラGCC 12+ / Clang 15+必須C++20 対応が条件（nvcc のホストコンパイラとして使う）。
CMake3.25+必須構成・依存検出・CTest。
Ninja—必須ビルド実行系（本ドキュメントの手順は -GNinja 前提）。
Python 3 + 開発ヘッダ3.10+既定 ONnamelist（入力デッキ）を初期化時に読む埋め込みインタプリタ。python3-dev 相当が必要。
pybind112.11+既定 ONnamelist → Config 変換。未導入なら自動取得。
HDF51.12+既定 ONスナップショット・履歴・チェックポイントの入出力。MPI ビルドでは並列 HDF5（--enable-parallel）を使う。
MPI3.1+opt-in（-DTENRYU_ENABLE_MPI=ON）複数ランク実行。GPU-aware MPI 推奨（なければホスト経由で中継）。
Hypre2.25+opt-in（-DTENRYU_ENABLE_HYPRE=ON）熱伝導の solver="hypre"（BoomerAMG+PCG）用。--with-cuda --with-gpu-aware-mpi でビルドされた Hypre が必要。
AmgX—opt-in（自動検出）2D FLD の線形ソルバ選択肢。find_package(amgx) が見つかれば既定で有効。
fmt / spdlog9.0+ / 1.12+内部依存ログ系。未導入なら自動取得。
Catch23.0+テスト用ctest の単体・統合テスト。未導入なら自動取得。
CLI112.4+内部依存run/verify/validate/freeze のサブコマンド CLI。未導入なら自動取得。

ネットワークについて。Catch2・spdlog・CLI11・pybind11 はシステムに見つからない場合、CMake の FetchContent が構成時にダウンロードする。したがって初回の cmake はインターネット接続があると楽である。オフライン環境（計算機センターの計算ノード等）では、これらをあらかじめ導入するか、ネットワークのあるログインノードで構成を済ませること。CUDA・HDF5・Python・MPI・Hypre は自動取得の対象外で、常に事前導入が要る。

CMake オプションの既定

オプション既定意味
CMAKE_CUDA_ARCHITECTURES70;80;89;90生成する SASS の対象世代。自分の GPU 1 種に絞るとビルドが速くなる（例: RTX 4090 なら 89）。
TENRYU_ENABLE_HDF5ONHDF5 入出力。OFF では出力・リスタートが使えない。
TENRYU_ENABLE_PYTHONONPython namelist の読込。OFF では .py デッキを読めない。
TENRYU_ENABLE_MPIOFF複数ランク実行。単一 GPU 利用なら OFF のままでよい。
TENRYU_ENABLE_HYPREOFF熱伝導の陰的ソルバ経路。
TENRYU_ENABLE_NVTXOFFプロファイル計装（Nsight 用）。
TENRYU_ENABLE_AMGX自動（検出時 ON）2D FLD の AmgX ソルバ。

事前チェックの実行例

ビルドに入る前に、次の 4 つが通れば必須要件はほぼ満たしている。

# GPU とドライバ（CUDA Version が 12.x 以上であること）
nvidia-smi

# CUDA コンパイラ（release 12.x であること）
nvcc --version

# ビルドツール
cmake --version     # 3.25 以上
ninja --version

# Python（3.10 以上・開発ヘッダの有無）
python3 --version
python3 -c "import sysconfig; print(sysconfig.get_paths()['include'])"

ここまで確認できたらビルドのページへ進む。CMake の構成段階で「パッケージが見つからない」と出た場合の対処も同ページにある。
