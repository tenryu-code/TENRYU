動作環境と要求スペック reference

TENRYU は NVIDIA CUDA 専用の GPU コードである。このページは、ビルドと実行に必要なマシン・GPU・コンパイラ・ライブラリの要求を一箇所にまとめる。ビルドのページは手順を、本ページは「その手順が成立する環境の条件」を扱う。

要点

  • 必須: NVIDIA GPU + CUDA Toolkit 12.x（12.0 以上）、C++20 コンパイラ（GCC 12+ / Clang 15+）、CMake 3.27+、Ninja、Python 3.10+（開発ヘッダ含む）、Boost のヘッダ。
  • 既定ビルドの CUDA アーキテクチャは、構成時に nvidia-smi で検出したローカル GPU の世代である（GPU が見えないホストでは 70;80;89;90、すなわち Volta/Ampere/Ada/Hopper の 4 世代向けの機械語を 1 つにまとめた fatbin）。継続的に検証している実機は A100（40/80 GB）・RTX 4090・RTX 3090 である。
  • MPI（Message Passing Interface）と Hypre（線形ソルバのライブラリ）は任意（既定 OFF）。HDF5 と Python は既定 ON。現行版には Hypre を使う計算の経路が無いので、Hypre は通常は要らない。テスト・ログ・CLI・Python バインディングの小依存（Catch2・spdlog・CLI11・pybind11）は未導入なら CMake 構成時に自動取得される — オフライン環境では事前導入が要る。Boost のヘッダは自動取得されず、常に事前導入が要る。
  • 開発・検証の実績はすべて Linux x86_64 上である。他 OS は未検証。

プラットフォームと GPU

対応バックエンドは NVIDIA CUDA のみである。HIP（AMD の GPU 向けのプログラミング環境）など、他のバックエンドは設計上の非対象である。GPU がなければビルドはできても実行はできない。基本の実行形態は 1 プロセス = 1 GPU で、単一 GPU なら MPI なしで動く。複数 GPU は MPI ビルド（後述）で 1 ランク（rank。MPI のプロセス）= 1 GPU として使う。

項目要求 / 既定備考
GPU ベンダNVIDIA のみCUDA 専用。他ベンダ GPU・CPU 単独実行は非対応。
GPU アーキテクチャ既定: 構成時に検出したローカル GPU（GPU が見えなければ fatbin 70;80;89;90）CMAKE_CUDA_ARCHITECTURES で変更可。理論上の下限は倍精度 atomicAdd が要る compute capability 6.0+（ARCHITECTURE §2.2）。sm_86（RTX 30 系）は sm_80 バイナリの前方互換で動く。
検証済みの実機A100 40/80 GB、RTX 4090（24 GB）、RTX 3090（24 GB）回帰・ベンチマークを継続実行している構成。VRAM の必要量は格子規模に依存する — 1D の基準問題は小さく、大規模 2D ほど要る。
OSLinux x86_64（実績）開発・CI（continuous integration、継続的インテグレーション）相当の検証・本番実行はすべて Linux。他 OS は未検証。
GPU ドライバCUDA 12.x 対応版nvidia-smi が表示する CUDA Version が 12.x 以上であること。

ツールチェーンとライブラリ

最低バージョンの正典はリポジトリの docs/ARCHITECTURE.md §2.2（CMake のみ最上位の CMakeLists.txt）である。要求は主に「必須」「既定 ON（外せるが通常は使う）」「任意（既定 OFF）」の三層に分かれ、ほかにテスト用・内部依存・解析用の依存がある。

依存最低バージョン層役割・注意
CUDA Toolkit12.0+必須nvcc・ランタイム・cuSPARSE・cuSOLVER・cuBLAS。cuRAND device API（Philox4x32-10）と NVTX（NVIDIA Tools Extension、プロファイル用の注釈）はツールキット同梱でリンク不要。
C++ コンパイラGCC 12+ / Clang 15+必須C++20 対応が条件（nvcc のホストコンパイラとして使う）。
CMake3.27+必須構成・依存検出・CTest。
Ninja—必須ビルド実行系（本ドキュメントの手順は -GNinja 前提）。
Boost（Multiprecision のヘッダ）指定なし（1.83 で検証）必須boost/multiprecision/cpp_int.hpp だけを使い、Boost のライブラリのビルドは要らない。CMake は版を検査しない。2D の ALE（arbitrary Lagrangian–Eulerian、任意ラグランジュ・オイラー法）のリマップで、多角形の厳密な切り取りと、その体積・モーメントの参照計算、および総和の順序に依らない厳密な和に使う（いずれも任意精度の整数・有理数）。1D だけを使う場合でも、CMake が構成時にこのヘッダを探し、見つからなければ構成が止まる。自動取得はしない。標準の場所に無いときは、-DTENRYU_EXACT_GEOMETRY_BOOST_INCLUDE_DIR=<dir>（<dir>/boost/multiprecision/cpp_int.hpp がある include ディレクトリ）で指定する。Debian/Ubuntu ではパッケージ libboost-dev で導入できる。
Python 3 + 開発ヘッダ3.10+既定 ONデッキ（deck。TENRYU の入力となる 1 個の Python ファイル）を初期化時に読む埋め込みインタプリタ。python3-dev 相当が必要。
numpy / matplotlib / h5py—解析用付属の解析ツール tools.tenryu_plot が使う。本体のビルド・実行には不要。
pybind112.11+既定 ONデッキから Config（C++ の設定構造体）への変換。未導入なら自動取得。
HDF51.12+既定 ONスナップショット・履歴・チェックポイントの入出力。ファイルはすべてランク 0 が書くので、逐次版の HDF5 で足りる。並列版（--enable-parallel）も使えるが、そのときはリンクに MPI が要る。
MPI3.1+任意（-DTENRYU_ENABLE_MPI=ON）複数ランク実行。GPU-aware MPI 推奨（なければホスト経由で中継）。
Hypre2.25+任意（-DTENRYU_ENABLE_HYPRE=ON）線形ソルバのライブラリ。現行版には Hypre を使う計算の経路が無く、ON にすると Hypre がリンクされるだけである。ON のビルドでは、熱伝導の solver="hypre" は 1D で警告のうえスーパータイムステッピング（super-time-stepping、STS）で解かれる。OFF のビルドと 2D では、入力検査が拒否する。ON のとき CMake は、CUDA 対応でビルドした Hypre（HYPRE_config.h に HYPRE_USING_CUDA があること）を要求する。
spdlog (fmt 同梱)1.12+ (fmt 9.0+)内部依存ログ系。未導入なら自動取得（fmt は spdlog の同梱版を使う）。
Catch23.0+テスト用ctest の単体・統合テスト。未導入なら自動取得。
CLI112.4+内部依存run/verify/validate/freeze のサブコマンド CLI。未導入なら自動取得。

ネットワークについて。Catch2・spdlog・CLI11・pybind11 はシステムに見つからない場合、CMake の FetchContent が構成時にダウンロードする。したがって初回の cmake はインターネット接続があると楽である。オフライン環境（計算機センターの計算ノード等）では、これらをあらかじめ導入するか、ネットワークのあるログインノードで構成を済ませること。CUDA・Boost のヘッダ・HDF5・Python・MPI・Hypre は自動取得の対象外で、常に事前導入が要る。

CMake オプションの既定

オプション既定意味
CMAKE_CUDA_ARCHITECTURES検出したローカル GPU（GPU が見えなければ 70;80;89;90）生成する GPU 機械語（SASS）の対象世代。GPU が見えないホストで構成するときは、実行する GPU 1 種に絞るとビルドが速くなる（例: RTX 4090 なら 89）。
TENRYU_ENABLE_HDF5ONHDF5 入出力。OFF では出力・再開（restart）が使えない。
TENRYU_ENABLE_PYTHONONデッキ（Python ファイル）の読込。OFF では .py のデッキを読めない。
TENRYU_ENABLE_MPIOFF複数ランク実行。単一 GPU 利用なら OFF のままでよい。
TENRYU_ENABLE_HYPREOFFHypre のリンク。Hypre を使う計算の経路は無い（上の表を参照）。
TENRYU_ENABLE_NVTXOFFプロファイル計装（Nsight 用）。
TENRYU_EXACT_GEOMETRY_BOOST_INCLUDE_DIR標準の場所を探すBoost のヘッダ boost/multiprecision/cpp_int.hpp がある include ディレクトリ。標準の場所に無いときに指定する。

事前チェックの実行例

ビルドに入る前に、次の 5 つが通れば必須要件はほぼ満たしている。

# GPU とドライバ（CUDA Version が 12.x 以上であること）
nvidia-smi

# CUDA コンパイラ（release 12.x であること）
nvcc --version

# ビルドツール
cmake --version     # 3.27 以上
ninja --version

# Python（3.10 以上・開発ヘッダの有無）
python3 --version
python3 -c "import sysconfig, pathlib; p = pathlib.Path(sysconfig.get_paths()['include'], 'Python.h'); print(p, 'OK' if p.exists() else 'MISSING')"

# Boost のヘッダ（標準の場所にある場合。他の場所に置いたときは、その場所を CMake に指定する）
ls /usr/include/boost/multiprecision/cpp_int.hpp

ここまで確認できたらビルドのページへ進む。CMake の構成段階で「パッケージが見つからない」と出た場合の対処も同ページにある。
