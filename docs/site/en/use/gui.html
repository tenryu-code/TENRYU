TENRYU Studio (GUI) reference

TENRYU Studio is a desktop application for creating TENRYU Python namelist decks through a form. It generates the deck live as inputs change and brings validation, saving, and local or server execution into one workspace. A saved deck also carries its form state, so a configuration can move between code and the GUI without a separate project file.

At a glance

  • Editing the center form immediately updates the Python deck in the right pane.
  • Pass both form validation and server-side tenryu validate before saving or running.
  • Keep the TENRYU-GUI-STATE comment to restore the complete form from a saved deck.
  • Three physics presets were run to completion on an RTX 4090 on 2026-07-31.

Obtaining and launching

Studio ships inside the repository's gui/ directory (there is no standalone distribution). The web core is pure web: for a development launch, run npm install in gui/, then run npm run bridge (the local execution bridge) and npm run dev (the Vite dev server, http://localhost:5173) side by side and open it in a browser. The Mac native app (the Tauri shell) can be built only on a Mac. See gui/README.md in the repository for the detailed procedure.

From form to run

Studio's left navigation follows the normal setup order: Presets, Basic, Materials, Geometry, Physics, Drive, and Output. The center pane contains the selected form, while the live deck in the right pane always shows the latest Python namelist. Missing required values or inconsistent combinations produce errors in place; deck generation resumes after they are corrected. This makes the TENRYU cgs + eV contract visible while editing: lengths are in cm, times in s, temperatures in eV, and densities in g/cm³.

The basic sequence is form → live deck → validate → save or run. A preset is a starting point, and every field remains editable after it is applied. Read the generated deck, resolve all validation errors, then save it to a file. The result is an ordinary Python deck: it can be run outside Studio with ./build/tenryu run deck.py and inspected in any text editor.

Round-tripping with TENRYU-GUI-STATE

Studio embeds a TENRYU-GUI-STATE comment near the beginning of every deck it saves. Opening that deck restores the entire form—including materials, regions, physics, drive waveforms, and output settings—and restarts live generation. The executable deck itself is therefore the unit to share or archive; there is no separate GUI project file to keep synchronized.

A saved deck remains valid Python and may be edited by hand. Removing the state comment, however, prevents Studio from reconstructing the form. If the embedded state and the hand-edited Python body diverge, reopening the file regenerates the deck from the embedded state. For a deck that will return to the GUI, retain the comment and make persistent changes through the restored form before saving again.

Run-validated 1D presets

In addition to a blank setup, Studio provides three physics presets. These were not merely accepted by the schema: each was run to its endpoint on an RTX 4090 on 2026-07-31 and checked for its characteristic physical result.

  • Radiation slab: a 120 eV Marshak drive and grey FLD produce a heat front near 35 µm at 1 ns, with a cold region still ahead of it.
  • Laser implosion capsule: a GXII-class 10 TW × 1 ns drive (GXII: the GEKKO XII laser — see the linked benchmark definition), DT + CH target, corona ramp, and 20-group FLD give about 86% absorption and bang near 1.4 ns. This preset's ≈86% is not comparable with the regression deck's 83–84% or the HELIOS campaign's ≈45% — the Examples page lists the three conditions.
  • Indirect-drive Tr(t): a Marshak waveform rising from a 120 eV foot to 200 eV follows stagnation at 4.2–4.5 ns and the subsequent rebound.

The Examples & presets page records the numerical inputs and measured values. When modifying a case, first retain an unmodified short reference run, then vary one input at a time. That makes changes in absorption, compression, and output cadence much easier to identify.

Validate and run on a server

Define an execution profile and TENRYU binary under Servers, then select that profile in the header. Run validate sends a temporary deck to the selected server and performs dry-run validation there. Run ▶ submits the validated setup to the same server. Run History retains its queued, running, completed, or failed status and provides access to the results. Without a configured server, deck generation and saving still work; run the saved file with the TENRYU command line on a suitable host.
