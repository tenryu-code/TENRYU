出力と解析 reference

TENRYU の 1 回の実行は、スナップショット（空間場）・履歴（スカラー時系列）・チェックポイント（再開用）の 3 種の HDF5 と、来歴ファイル（凍結設定・実行情報・ログ）を生成する。このページは何が出力されるかの全列挙である — ファイルの種類と命名、スナップショットの全グループとデータセット、履歴の全チャネル、チェックポイントの追加内容、そして読み方。データ型・配列形状まで含む正典はリポジトリの docs/SPECIFICATION.md §7（要約は docs/OUTPUT_SCHEMA.md）である。

要点

  • 3 種の HDF5: スナップショット <name>_NNNN.h5、履歴 <name>_history.h5（追記型）、チェックポイント <name>_ckpt_NNNN.h5。出力間隔は「N ステップごと」（plot_every 等）と「T 秒ごと」（plot_every_s 等）の OR で発火する。
  • 全数値データセットに units 属性が付く。mesh/・hydro/ のデータセット名は内部の State フィールド名と 1:1 対応する。
  • 爆縮の停滞期のピークは短い — GXII 級の laser_capsule プリセットでは約 15 ps — ため、ピーク値はスナップショットではなくステップごとの履歴（implosion/*）から読む。
  • 同じ出力ディレクトリへ再実行すると、上書きせず _001 のような連番ディレクトリに書かれる。「結果が変わらない」と思ったらまず出力先を確認する。

ファイル構成・命名・出力間隔

ファイル命名出力頻度用途
スナップショット<case>_NNNN.h5（4 桁ゼロ詰めサイクル番号）plot_every ステップごと または plot_every_s 秒ごと（OR 論理）場の可視化・後処理。物理時刻はルート属性 t。
履歴<case>_history.h5history_every / history_every_s（OR、追記）スカラー診断量の時系列。extensible dataset に毎回追記する。
チェックポイント<case>_ckpt_NNNN.h5（ランク別ファイルでは _rNNNN が付く）checkpoint_every / checkpoint_every_s（OR）リスタート。checkpoint_keep_last 個だけ保持し古いものは自動削除。

<case> は Main.name、未指定なら namelist ファイル名（拡張子なし）である。並列 IO は役割別で、スナップショットは並列 HDF5（MPI-IO、collective write）で単一ファイル、履歴は rank 0 のみが書き、チェックポイントはランク別ファイルになる。ディレクトリ全体の配置は次のとおりである。

outputs/<name>/
├── results/                  ← スナップショットと履歴
│   ├── <name>_0000.h5
│   ├── <name>_0001.h5
│   └── <name>_history.h5
├── config/                   ← 来歴（凍結設定と namelist の写し）
│   ├── <name>_frozen.json
│   └── <name>_namelist.py
├── checkpoints/              ← リスタート用
│   └── <name>_ckpt_0100.h5
├── log/                      ← 実行ログ
└── run_info.json             ← 実行の要約（終了状態など）

出力先が既に存在して衝突する場合は、上書きせず outputs/<name>_001/ のような 3 桁連番の別ディレクトリへ書く。deck を編集せずに出力先を変えたいときは tenryu run <deck> --output-dir <dir> で実行時に上書きできる（新規 run 専用。restart との併用は ConfigError）。

スナップショットの全データセット

ルート属性は t（時刻 [s]）、cycle、geometry（"1D_SPH"|"2D_RZ"）、n_cells、n_nodes、n_groups、n_materials、schema_version である。1D では配列は 1 次元フラット、mesh/x_z・v_z は省略される。以下、グループごとに列挙する（「optional」は生成条件付き）。

metadata/ — 来歴

データセット内容
namelist_source実行した namelist（Python ソース全文）。
frozen_config凍結設定 JSON。属性として git_hash・build_type・cuda_arch・gpu_name・n_ranks・rng_seed を持つ。
group_bounds_eV輻射群境界 [eV]（長さ G+1）。

mesh/ — 節点と接続

データセット内容
x_r, x_z節点座標 [cm]。x_z は 2D のみ。
v_r, v_z節点速度 [cm/s]。v_z は 2D のみ。
cell_material_idセルの代表材料インデックス（多材料セルは体積分率最大、同率なら小さい方）。
topology/v2/・v3/・v4/optional。マルチブロックメッシュの接続（v2: 3 ブロック、v3: half-butterfly 5 ブロック — block/seam 表と CSR 接続、v4: 五角形帯の cell_nverts と corner_stride 属性）。単一ブロックでは省略。構成の詳細は 2D メッシュ参照。

hydro/ — セル中心の流体・熱力学状態

データセット内容
rho, Te, Ti密度 [g/cm³]・電子/イオン温度 [eV]。
ee, ei電子/イオン比内部エネルギー [erg/g]。
Pe, Pi, Qvisc電子/イオン圧力・人工粘性圧 [dyne/cm²]。
mass, volセル質量 [g]・体積 [cm³]。
zbar平均電離度。
volFrac材料体積分率 [N_cell, N_mat]（多材料時）。
shock_timeoptional。最後に衝撃波を検知した時刻 [s]（post-shock 系機能の有効時）。
adaptive_av_gate, adaptive_av_mode_celloptional。適応 AV のゲート履歴と可視化マスク（adaptive_av.enabled=True 時）。
corner_massoptional。2D のサブゾーンコーナー質量 [g]（ラグランジュ不変量）。
eta_compatibleoptional。旧 compatible 診断の体積差不整合 [cm³]。
per_material/v1/optional。材料別保存の schema skeleton（Numerics.materials.per_material_conservation_enabled=True 時）。

diagnostics/ — スナップショット側の物理診断（optional）

グループ有効条件と内容
areal_density/v1/Diagnostics.areal_density.enabled=True。角度列 angles_deg と面密度 rhoR [g/cm²]、optional の hotspot ガストレーサ版 rhoR_hotspot_tracer。
hotspot_gas/v1/Numerics.diagnostics.hotspot_gas.enabled=True。停滞期ホットスポットの Te/Ti 統計（mean/p10/p50/p90）、エネルギー（internal/kinetic/total とその初期値）、仕事プロキシ、定義文字列。

radiation/ — 輻射場と輻射診断

データセット内容
energy_density群別輻射エネルギー密度 E_g [erg/cm³]（[N_cell, G]）。
rad_dep, rad_emit当該ステップ累積の吸収・放出 [erg]（群別）。
deposited_power吸収パワー密度 [erg/cm³/s]（= rad_dep/(VΔt)、可視化用）。
boundary_flux群別境界流出 [erg/s]。
momentum_dep運動量沈着（診断のみ、流体非結合）。
fleck_factor2D FLD のみ。セルの Fleck 因子（診断はグレイ G=1 で有効）。
sn_tau_R, sn_reduced_flux, sn_ap_alpha2D SN のみ。AP face_blend 診断（光学的厚さ・換算流束・面重みの各プロキシ）。
diag_rad_*（10 種）1D SN の出力専用診断: E_pre/E_post/emission_at_Tn/emission_at_Tnp1/absorption/clip_energy/clip_full_deficit/chi_opacity/F_first_moment/E_star_flux、および diag_stream_theta・diag_ap_alpha_face。リスタートの状態復元には使われない。
ddmc_flag退役 imc_ddmc 経路のみ有意。現行 FLD/SN では意味を持たない。

laser/ — レーザー（Laser.enabled=True 時のみ）

データセット内容
deposited_powerレーザー沈着パワー密度 [erg/cm³/s]。
absorption_fraction全体吸収率（absorbed/incident）。
ray_densityレイ初期配置密度 [1/cm³]。
A_Q_r_shells, A_Q_z_shells2D のみ。シェル（r 添字固定の z 方向セル列/z 添字固定の r 方向セル列）ごとの沈着非対称度 \((q_{max}-q_{min})/(q_{max}+q_{min})\)。q は各セルにそのステップで沈着したレーザーエネルギー [erg]。
mesh/ray_output_trajectory=True の非 skip ステップ（= レイトレースを実行したステップ。Laser.raytrace_skip の間引き再利用ステップでは出力されない）のみ。レーザー専用の独立格子 LaserMesh（流体メッシュとは別の 2D RZ 構造格子 — レーザー参照）の節点座標・\(\hat n_e\)（電子密度の対臨界密度比）・T_e・Z̄・密度勾配・n_crit。
rays/ray_output_count>0 の非 skip ステップのみ。レイの初期位置・方向・パワー（1D: R0/Z0/vR0/vZ0、2D: x0/y0/z0/vx0/vy0/vz0）とビーム ID。
rays/trajectory/ray_output_trajectory=True 時。CSR 形式の軌跡（offsets・step_count・位置列・残存パワー列）。可視化のレイ重ね描きの元データ。

mode="radial_absorption_1d" では物理的なレイ軌跡がないため、deposited_power と absorption_fraction は通常どおり出力されるが rays/ 系は空または未作成となる。なお holo/ と difference/ のグループは退役 imc_ddmc 系経路の専用出力であり、現行の FLD/SN 実行では対象外である。

履歴の全チャネル

results/<name>_history.h5 は追記型の時系列である。ルートには t・cycle・dt の 3 本と、完了時に停止理由を記す属性 termination_reason（"t_end"|"max_steps"）が入る。

energy/ — エネルギー台帳（常時）

チャネル内容
laser_incident / laser_deposited / laser_escapedレーザーの入射・吸収・未吸収の累積 [erg]。入射と吸収の比が吸収率になる。
marshak_in / radiation_escapedMarshak 境界からの入射累積と、輻射の境界流出累積 [erg]（全群合算）。
pdv_boundary境界 PdV 仕事の累積 [erg]。
kinetic / internal_electron / internal_ion / radiation_field運動・電子内部・イオン内部・輻射場の各エネルギー合計 [erg]。
numerical_loss数値的喪失の累積 [erg]。
floor_injected / safety_injected / redistribution_unresolved / solver_residual床補正・安全補正・ALE 再分配未解決分・ソルバ残差の各注入量 [erg]（診断専用、保存誤差の分子には含めない）。
conservation_error相対保存誤差 ε_budget（NUMERICS §10.2 の恒等式に基づく）。
E_volume_in / E_total / dE_total / E_denom内部診断（境界体積仕事・全エネルギー・その差分・保存誤差分母）。
phase_diagnostic/optional（Numerics.diagnostics.phase_resolved_energy=True）。hydro 前後・ALE 後の物質エネルギーと、相ごとの内部/運動エネルギー差分。
ale_closure_audit/optional（Numerics.ale.ke_conservation_closure_audit=True）。ALE の運動エネルギークロージャ監査（K/I の分解と残差、床カウンタ）。

グループ / チャネル内容

検証ページで引用される基準回帰の要約指標は、これらの時系列の時間方向の縮約である: rho_peak_max = implosion/rho_peak の最大、rhoR_max = implosion/rho_R の最大、Tc_max = implosion/center_temperature の最大、shell_r_min = implosion/shell_radius_min の最小。

警告: 出力間隔によるピークの取り逃がし

スナップショットの出力間隔はデッキごとに設定するが、爆縮の停滞期のピークは非常に短いことがある — GXII 級の laser_capsule プリセットでの実測（2026-07-31）では約 15 ps。出力の時刻がピークの前後に来てしまうと、スナップショット中の最大密度は真のピークを大きく過小評価する。鋭いピークの値とその時刻はステップごとの履歴にある implosion/rho_peak から読み、スナップショットはピーク前後の空間構造を調べるために使うこと。

チェックポイントの追加内容とリスタート互換

チェックポイントはスナップショットの内容に加えて、再開に必要な内部状態を保存する。

グループ内容
hydro_flags/hydro_activeセルの流体活性マスク。
rng/乱数状態（rng_counter・global_id）。
time_state/t・step・dt・累積エネルギー項・user_seed。再開時の Δt はここから引き継がれる。
output_state/次回出力予定時刻（t_next_plot・t_next_history・t_next_checkpoint）。
particles/退役 Monte Carlo 経路の粒子プール（現行 FLD/SN では対象外）。

リスタートの互換規約: schema_version が現行と同じなら通常読込、古い（または欠落）なら不足項目を既定値で補う後方互換読込、新しいなら読込拒否。凍結項目（次元・メッシュ・材料・群数・seed・群境界）が不一致なら再開は拒否される。再開の指定方法は実行ページを参照のこと。

来歴: frozen JSON・run_info・ログ

config/<name>_frozen.json は、既定値を解決した設定の全体、初期化時に表へ変換した関数の情報、その元データのハッシュの記録である。「入力したつもりの値」ではなく実行が実際に受け取った構成を監査する一次資料であり、再現・比較の際は deck とともに保管する。run_info.json は実行の要約、log/ には実行ログが残る。「設定が効いたか怪しい」ときは frozen JSON → log の warning の順に見るのが早い。

読み方: CLI・付属ツール・Scope

構造の確認は HDF5 標準ツールで足りる。

h5ls  outputs/<name>/results/<name>_0010.h5          # グループ一覧
h5dump -H outputs/<name>/results/<name>_history.h5  # ヘッダ構造

最短の可視化は付属の tenryu_plot（tools/）である。サブコマンドに profile（空間プロファイル）・history（時系列）・spacetime・summary・compare・spectrum などがある。

python3 -m tools.tenryu_plot --help                  # 一覧
python3 -m tools.tenryu_plot profile outputs/<name>  # 空間プロファイル
python3 -m tools.tenryu_plot history outputs/<name>  # 時系列

Python で直接読むなら h5py が最短である。全数値データセットに units 属性が付き、配列長は場の配置（セル数・節点数・セル×材料・セル×群）に応じて変わるため、ルート属性・形状・単位を合わせて読み取ること。

import h5py
f = h5py.File("outputs/<name>/results/<name>_0010.h5")
Te = f["hydro/Te"][:]; r = f["mesh/x_r"][:]
print(f["hydro/Te"].attrs["units"])   # -> "eV"

対話的な探索と実行どうしの比較には TENRYU Scope（アーキテクチャ参照）を使う。ビューアで着目すべき時刻と量を見つけ、最終的な図は凍結後の設定と明示したスクリプト引数から作ると、対話的な解析と再現性を両立できる。
