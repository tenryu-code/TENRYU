TENRYU

A CUDA-native Lagrangian/ALE (arbitrary Lagrangian–Eulerian) radiation-hydrodynamics code for laser-driven high-energy-density (HED) and inertial-confinement-fusion (ICF) physics, in 1D spherical/cylindrical/planar and 2D axisymmetric (RZ) geometry.

TENRYU couples compatible Lagrangian hydrodynamics with multigroup radiation transport, nonlocal electron conduction, laser ray tracing with inverse-bremsstrahlung absorption, cross-beam energy transfer (CBET), hot-electron generation and transport, tabulated or analytic equation of state (EOS) and opacity, and nuclear burn. The radiation transport is solved by flux-limited diffusion (FLD) or by discrete ordinates (SN). Most of the computation runs on the GPU; the experimental reconnection-based ALE feature reale_v2, which rebuilds the mesh connectivity, runs mainly on the host (CPU). The unit system is fixed to cgs + eV. A form-based GUI (TENRYU Studio) generates decks (a deck is the single Python file that is the input to TENRYU) and round-trips them between the code and the GUI. This documentation describes TENRYU version 1 (v1); see Nomenclature & conventions for the version notation, abbreviations, and symbol table used throughout.

Quick facts

VersionTENRYU v1 (this documentation's baseline; tenryu --version prints the version (1.0.0-beta.1) and the source revision; the nomenclature explains the notation)
Geometry1D_SPH (spherical, cylindrical, or planar via Mesh.geometry_1d); 2D_RZ (axisymmetric RZ)
MeshLagrangian and ALE; structured, polar, and multiblock
ComputeCUDA (exercised hardware is sm_80+ — System requirements), with MPI on a single rank or on several ranks (a rank is one MPI process)
Unitscgs + eV (fixed)
InputsDecks (Python files)
OutputsHDF5 snapshots (the fields at one time) and history (the time series of scalar quantities at every step); read them with Studio and with Scope, a sister application of Studio for inspecting and comparing the HDF5 fields and history
