Verification philosophy reference

TENRYU verification accumulates evidence from small analytic gates with closed-form solutions and invariants, through goldens of a fixed deck and run-to-run reproducibility, to integrated 2D RZ test suites and cross-code benchmarks. A higher gate class does not replace a lower one: each is a different oracle (a criterion that decides whether a result is correct) for a different failure class. Changes must not regress applicable gates, and exceptions require a documented scope and rationale.

At a glance

  • Analytic gates compare against known solutions, independent integrals, conservation identities, or convergence, and localize sign, unit, coefficient, and boundary errors.
  • A golden is a change detector for one grid and one set of run conditions, not proof of correctness or grid convergence.
  • Deterministic 1D paths require bitwise run-to-run identity with the same binary, input, and GPU configuration.
  • In 2D RZ as well, the floating-point sums that enter the state or the time step in one step run in a fixed order, and two runs of the same configuration must agree bitwise. Noise bands (bands, calibrated from the scatter of same-configuration replicas, that set how large a difference is accepted) apply only to paths whose replicas differ, deck by deck and metric by metric.

What verification answers

Verification asks whether the implemented numerical method solves its equations and discretization as specified. Validation — whether the modeled physics adequately agrees with experiment — is a different question. TENRYU checks the hydrodynamics, conduction, radiation, and laser kernels against known or reference solutions and convergence, then tests unit boundaries, conservation through the energy ledger, and coupling between modules. Small discriminating tests are especially important for failures such as confusing mass opacity \(\kappa\) [cm²/g] with length opacity \(\sigma\) [cm⁻¹], where a run may finish while the physics is wrong by a large factor.

The foundational organization is unit, integration, and regression, but operationally five gate classes make the evidence clearer. Small gates narrow the source of a failure. Coupled test suites ask whether individually correct components remain consistent inside the production time loop, mesh update, EOS closure, and energy ledger. Cross-code benchmarks expose trends and implementation differences, but they cannot substitute for internal verification or experimental validation.

This ordering is not a simple ranking of strength. An analytic gate has a powerful oracle over a narrow surface; an integrated test suite covers a broad surface with many components at once. The test suite cannot retire the analytic test because compensating errors can hide a wrong sign in one operator. Conversely, passing every unit gate cannot expose coupling defects such as the wrong operator order, stale EOS state, an inconsistent mesh update, or double injection of a source.

Designing oracles and tolerances

A useful gate does not build its reference by calling the same production helper that could contain the defect. Where practical, TENRYU uses an independent integral, analytic shock position, discrete eigenvalue, or published solution. Measurements follow the problem: Sedov and Noh inspect front location, plateau, and conservation; multigroup Marshak uses an independent Planck integral; Beer–Lambert checks a known optical depth. Mere run completion is a smoke test, not an accuracy oracle.

Tolerances are properties of the oracle and numerical noise, not one convenient percentage applied everywhere. A deterministic attenuation trace can use a tight relative error. A shock-capturing profile must account for grid error and the measurement estimator. A stochastic method needs confidence intervals or particle-count convergence. A physical model band is also kept separate from discrete-operator accuracy: widening a band must not make a known model limit appear certified.

Goldens and re-baselining

The 1D FLD golden for GXII (GEKKO XII, the laser benchmark defined on the Verification page) is a production-trajectory regression through laser deposition, hydrodynamics, conduction, two-temperature matter, and FLD. Rather than comparing only a final file, it takes the absorbed laser energy as the cumulative value at the end of the run, extracts bang time, rho_peak_max, areal density rhoR_max, and central temperature Tc_max_eV from the history time series, and applies each metric's tolerance. A mismatched run_profile (a string recording the run conditions, such as the grid and the run length) fails the comparison, preventing a shortened run or different grid from masquerading as the same baseline.

A golden is a change detector on the same grid and run conditions. Agreement does not prove analytic correctness or grid convergence. Re-baselining requires a known bug fix, an intentional physics-algorithm or baseline-parameter change, or another explicit reason approved by the code owner. The update must state why, quantify old-to-new differences, provide convergence data across resolutions, and receive review. A currently failing run, or the fact that copying its values would make CI green, is not a rationale. Relaxing a tolerance follows the same policy.

Reproducibility requirements

A deterministic 1D path must produce bitwise-identical fields and primary diagnostics between replicas using the same binary, deck, and GPU configuration. A physics gate may retain a percent tolerance for toolchain portability, but that width does not authorize same-configuration run-to-run drift. Fixed-order reductions and private accumulation, such as the deterministic 1D laser-deposition path, are therefore part of the algorithm's specification. The requirement is the same numerical trajectory, not merely two answers near one target.

In 2D RZ as well, the floating-point sums that enter the state or the time step within one step are computed in a fixed order that does not depend on the order in which threads run. A sum into a node or a cell is added by one thread per target in ascending order of the connectivity-table key, and the laser deposit rounds an exact 128-bit fixed-point integer sum once. Two runs of the same configuration are therefore required to match bitwise in 2D RZ as well. A mismatch indicates a sum that is not yet in fixed order, or another remaining source of nondeterminism. A noise band is used only on a path whose replicas are known to differ, with a band self-calibrated from same-configuration replicas or calibrated once from an ensemble of runs and then fixed, and this criterion names its deck and metrics. It is not a blanket tolerance for all 2D results: deterministic intermediates, 1D legs, and quantities unrelated to the noise remain bitwise or retain their original tight gates.

Conditions for accepting a change

A change to physics, numerics, parallel reduction, or an output metric must pass the affected existing gates and add a check for any newly guaranteed property to the appropriate class of the taxonomy. An improved integrated result cannot offset a regressed analytic gate, and updating a golden cannot hide the regression. If an exception is necessary, its test, metric, configuration, physical or numerical rationale, alternative oracle, and whether the exception is time-limited or permanent must be documented. A skip is not a pass; an environment-dependent non-run retains its status and execution log.

The purpose is not to prevent change, but to make clear what changed, which evidence supports it, and which guarantees remain. Analytic, golden, reproducibility, test-suite, and cross-code evidence need not produce the same kind of answer. Each watches its own failure class, and every applicable guarantee must remain non-regressed after the change. That layered, explicit evidence is how TENRYU decides whether to accept a change.
