MPI decomposition reference

TENRYU's MPI (Message Passing Interface) domain decomposition assigns one GPU (graphics processing unit) to each rank (an MPI process), and every rank retains arrays of the full global size while updating only its owned window. Compacting the arrays to the owned window and remapping them to local indices is not used. The partition boundaries are coupled by a halo exchange of ghost regions, which are copies of the values that a neighboring rank owns. Because the CUDA kernels (functions that run in parallel on the GPU) act on explicit index ranges, a one-rank run is the special case of the same implementation in which the owned window is the whole range. Terms specific to this calculation are defined in the terms section.

At a glance

  • All ranks share one global index space; each rank writes only its owned cell and node ranges.
  • The ghost width is fixed at two layers. Exchanges overwrite natural global-index positions with the owner's bits.
  • Owned partials normally use MPI_Allreduce(SUM), which does not generally guarantee bitwise identity when the rank count changes.
  • Features not audited for multiple ranks are never run silently, by the deferral guard: when more than one rank is present, they are rejected with an explicit error at the start of the run (some at the first call of the operator). The 2D default settings (electron conduction on, multigroup-diffusion radiation, the midpoint scheme) fall under this, so a 2D deck with default settings does not run on more than one rank.

Why this decomposition

The constraints are one MPI rank per GPU, physics kernels that are deterministic, and CUDA kernels already expressed over explicit index ranges. The layout chosen over compacted local-index alternatives makes every rank hold global-size arrays but own only a window. It trades memory for simplicity and safety: there is no local-index remapping to get wrong, one-rank execution is the same code with a full-range window, and an operator is ported to MPI by narrowing the range over which its CUDA kernels may act.

Stencil physics (a stencil is the set of neighboring points that must be read to compute one value) still needs neighboring state. Two ghost layers cover every stencil in the set audited for multiple ranks. Two stencils set the width. One is the 1D checkerboard PQ filter, an odd–even filter applied to the total cell pressure \(P+Q\), the pressure plus the artificial-viscosity pressure. To compute cell \(i\), it reads \(P+Q\), the density \(\rho\), and the flag that marks cells where hydrodynamics is active (hydro_active) out to cells \(i\pm2\). The other is the electron odd–even flux, a conservative face filter applied to the 1D electron energy \(e_e\) to suppress checkerboard noise. Whether a flux is set on the face between cell \(i-1\) and cell \(i\) is decided by reading the two cells adjacent to the face plus one further cell on each side, so the flux on this face reads \(e_e\) in cells \(i-2\ldots i+1\). Updating a cell at the edge of the owned window therefore reads up to two cells outside it. Shared node planes use owner-overwrite semantics, so the value of a node is unambiguous: a ghost is a copy of the owner's value and is never merged with it.

Reproducibility and scope are explicit. Owned partials normally combine with MPI_Allreduce(SUM), so bitwise identity is not promised across different rank counts; for a fixed rank count, deterministic kernels remain deterministic. Features not audited for multiple ranks stop with an error at the start of the run instead of running incorrectly. Far cells are stale-but-finite by design, but physics must never read them. The launch range of each CUDA kernel states what the kernel may read and write, so a read outside it can be detected by comparing runs with different rank counts.

  • cw, nw, pw, fw: these are launch-range roles, not array copies — local variable names that appear in the source code only, never in namelists or output files. The table in the owned-window decomposition section gives the range and use of each.
  • Two ghost layers: the checkerboard PQ filter reaching \(i\pm2\) and the electron odd–even flux reaching \(i-2\ldots i+1\) set the width; audited one-layer stencils fit inside it.
  • Shared node planes: neighboring ranks may compute the same node, but owner overwrite makes the value of the node unique.
  • 2D layout: with the flattened index \(c=i\,n_z+j\), an r-slab is a contiguous span of the global array.

Terms used in this calculation

TENRYU's MPI implementation keeps a global-size array on every rank, so it needs words for which entries a rank updates and which entries are copies of another rank's values. The terms below carry meanings specific to this layout, so they are defined together. General MPI vocabulary (rank, collective communication, non-blocking communication) is not explained.

Owned window

The owned window is the contiguous interval [begin, end) of the flattened index that one rank updates (the blue cells in Figure A). The flattened index is \(c=i\,n_z+j\) in 2D_RZ (\(i\) and \(j\) are the cell numbers in the r and z directions, and \(n_z\) is the number of cells in z) and is simply the radial cell number in 1D_SPH. With r-slabs, a slab is a contiguous interval of the flattened index, so a window can describe it. There is an owned window for cells and one for nodes: the cell windows of all ranks tile the cells without overlap, while the node windows of neighboring ranks share one node plane at their boundary (Shared node planes and owner overwrite).

Every rank holds a global-size array, so each CUDA kernel must be told which range it may update, as (begin, end). With the range explicit, a CUDA kernel launched over the owned window updates each cell on exactly one rank (except in the stages of replicated computation, where every rank computes the whole line), and an error that uses stale values outside the range shows up as a difference in the comparison between runs with different rank counts (Verification). On one rank, the owned window is the full range [0, n).

1D_SPH splits the cell line, and 2D_RZ splits the r direction, into as many slabs as there are ranks (the value given to -n of mpirun). In 2D_RZ, Parallel.decomposition.dims, when set, must be [number of ranks, 1]; when unset, the driver chooses this value. The remainder of the cell count divided by the slab count is assigned one cell at a time, starting from the lowest-numbered rank. The number of cells owned by each rank must be at least Parallel.decomposition.min_cells_per_rank (default 8). Initialization stops if, in 1D, the cell count is less than the product of the rank count and this value, or if, in 2D, the quotient (rounded down) of the r-direction cell count by the rank count, or the z-direction cell count, is less than this value. Studio does not write a Parallel block, so these defaults are the values used when the deck does not set them.

In the implementation, State::owned_cell_window(n) returns the owned-cell window, State::owned_node_window(n) the owned-node window, and State::owned_cell_window_ghost(n, stride) the owned-cell window widened on the sides that have a neighbor rank. At call sites, the local variables that receive them are written cw, nw, pw, and fw (pw and fw are the names that receive the result of owned_cell_window_ghost in the hydrodynamics and ALE (arbitrary Lagrangian–Eulerian) implementations). The widening applies only on the sides that have a neighbor rank: one cell in 1D, and one r-row (\(n_z\) cells) in 2D. The use of each window is given in the table of the owned-window decomposition section.

Ghost region and ghost width

The ghost region is the copy of the values owned by a neighboring rank that lies just outside the owned window. It is not a separate local array; it sits at the natural global-index positions (the yellow cells in Figure A). The implementation and the namelist keys also use the name halo (halo_exchange, Parallel.halo).

The ghost width is the number of layers kept outside the owned window: two cells in 1D and two r-rows in 2D. In the implementation, PartitionInfo::ghost_layers is fixed to 2 when there are two or more ranks and is 0 on one rank. The repository's docs/NUMERICS.md §12.2.1 writes this width as \(n_{ghost}\), but the code has no identifier of that name. The namelist key Parallel.halo.ghost_layers (default 1) is read and checked to be at least 1, but it does not determine the width.

The width of two is set by the farthest position that the update of a cell at the edge of the owned window reads (Why this decomposition). The ghost region is refreshed by an exchange after the owning rank writes and before the first process that reads the ghosts (Ghost and halo exchange). With fewer than two layers, the widest stencil would read stale values outside the owned window.

Shared node planes and owner overwrite

A shared node plane is the set of nodes at a slab boundary that lie in the owned windows of both neighboring ranks (all nodes with a given r-direction node number; one node in 1D). The owned node window is one node plane longer in r than the owned cell window, so the node plane at a boundary belongs to both ranks. Both ranks compute this node from the same inputs with the same expression.

Owner overwrite is the rule that unifies the values on a shared node plane to those of the lower-numbered of the two ranks. In a node exchange, the lower-numbered rank's values overwrite the values of the same nodes held by the higher-numbered rank. By this rule, the position and velocity of a boundary node have the same bit pattern on both sides. Owned cell windows do not overlap, so cells do not need this rule; the ghost cells are simply overwritten by the owner's values.

Far region and “stale-but-finite”

The far region is the region outside the owned window and the ghost region. Every rank holds a global-size array, so entries in this region exist, but the exchange does not update them (the hatched cells in Figure A).

Stale-but-finite is the condition imposed on the values in the far region. The values may be old but must be finite, and they must not affect the results in the owned window, convergence decisions, retry decisions, or diagnostics. A CUDA kernel that scans the whole mesh (for example, the recomputation of the mesh geometry) may produce finite but meaningless values in the far region. To make this condition hold, the partial sums of dot products, minima, maxima, and totals are always restricted to the owned window, and the mesh validity checks are made over the owned window and the ghost region only.

Replicated computation

Replicated computation is the method in which every rank computes the same stage redundantly, from the same inputs and in the same order. The implementation's variable names (such as replicated_radiation_1d) and the repository's docs/NUMERICS.md §12.4 call it replicated. In 1D it is used for radiation (flux-limited diffusion (FLD) and discrete ordinates (SN)), burn, the implicit electron solve and the ion conduction, and the laser ray tracing; in 2D it is used for the laser ray tracing. Before such a stage, the owners' values are gathered with MPI_Allgatherv into the whole line (in 2D, the whole mesh) on every rank, so the inputs have the same values as in a one-rank run. The result does not depend on the rank count, and the summation order of MPI_Allreduce(SUM) does not enter it, so bitwise identity can be tested. The amount of computation is the same as in a one-rank run, so adding ranks does not make this stage faster.

Deferral guard and audit

A deferral guard is the processing that rejects, as an error, a feature whose checks for use on multiple ranks have not yet been completed, when the rank count is two or more. Running a feature without those checks would miss references to stale values in the far region and mismatches between ranks in collective communication (a cause of deadlock).

The checks that this page and the comments in the implementation call an audit confirm that the CUDA kernels of the feature do not read outside the owned window, that the exchange comes right after the owned window is written and before the first process that reads it, and that the order and number of collective communication calls agree on all ranks.

The error messages call the current MPI implementation “MPI v1” (for example, MPI v1: 1D void regions are not supported multi-rank yet). Some rejections are made by the driver at the start of the run, and others by the operator of the feature at its first call. The table in the section on features rejected on multiple ranks lists the rejected features.

Comparison tiers (bitwise identity, band, envelope)

The check of runs with different rank counts (the ctest label mpi_gate) compares the owned-window dumps that each rank writes at the end of the run (output with TENRYU_MPI_DUMP_OWNED) with the same range of a one-rank run (tests/parallel/run_parallel_gate.py). The fields compared are density, electron and ion energy and temperature, mass, volume, node positions and velocities, radiation energy, laser deposit, and artificial-viscosity pressure. There are three tiers of comparison, and each test is assigned one.

  • Bitwise identity (bit): every entry of every field equals the one-rank run exactly. It is used for the 1D tests.
  • Band (band): for each rank's owned window and each field, the maximum difference from the one-rank run, divided by the maximum absolute value of the whole field in the one-rank run, is at or below a tolerance. The tolerance is \(10^{-13}\) for the 2D SN and 2D burn tests.
  • Envelope (envelope): used for the 2D LaserMesh test. Fields other than the laser deposit are compared with a band of tolerance \(10^{-12}\). The laser deposit is judged as follows. The one-rank run is repeated three times, and three statistics are computed from the differences among the runs: the maximum ULP (unit in the last place, one unit of the least-significant bit of a floating-point number) distance among the entries that differ, the number of entries that differ, and the fraction of the total deposit carried by those entries. The largest value of each statistic over the pairs of runs, multiplied by a margin factor of 4, gives a bound; if the bound is below a floor (4 ULP, 8 entries, fraction \(10^{-12}\)), the floor is used. The same three statistics are computed from the differences between the multi-rank run and a one-rank run, and the test passes if each is at or below both this bound and the fixed bound recorded in tests/parallel/gate_caps.json (250 ULP, 10500 entries, fraction 1). The ray records (TENRYU_LM_INVARIANT_DUMP) must agree byte for byte among all ranks and all one-rank runs.

The 1D snapshot tests (tests/parallel/run_snapshot_gate.py) compare every numeric dataset of the output files (metadata excluded) bitwise with a one-rank run. The reproducibility checks on the Verification page classify the reproducibility checks as a whole.

Owned-window decomposition

For 1D_SPH, the global cell line is split statically into contiguous radial slabs. 2D_RZ is split into r-slabs, contiguous in the flattened index \(c=i\,n_z+j\). A multi-rank 2D run is limited to r-slabs; the driver rejects z-slab and two-direction splits. Arrays are not remapped to compressed local indices. Every rank allocates them globally, so entries outside the owned window can be addressed with the same indices, but only the owner updates physical state.

The short window names seen in the implementation (see Owned window) describe launch-range roles, not separate array copies. The table gives the range and use of each window, and Figure A shows an example of the ranges for rank 1.

Ghost and halo exchange

The ghost width is two layers (Ghost region and ghost width). The 1D checkerboard PQ filter and the electron odd–even flux reach two cells outside the owned window; this width also covers the one layer required by the 1D conduction face coefficients (computed up to one cell beyond the owned window; see Electron & ion conduction), the scatter of the hydro corner force (see Lagrangian hydrodynamics), and the Winslow rezoning iterations (see ALE). Ghosts occupy natural global-index positions and match the owner's bits after exchange.

Values in the far region (stale-but-finite) may be stale, but must remain finite and cannot influence owned results, convergence decisions, retry decisions, or diagnostics. The partial sums of dot products, minima, maxima, and totals are therefore always restricted to the owned window.

Exchange occurs after an owned write and before the first ghost consumer. Hydro entry exchanges thermodynamic cell fields; predictor–corrector position commits are followed by node position and velocity exchange. The exchange implementation also has corner transfers with diagonal neighbor ranks for 2D decompositions in two directions; multi-rank 2D runs are limited to r-slabs, however, so the only transfers actually made are with the left and right neighbor ranks. GPU-aware MPI (CUDA-aware MPI) performs device pack, MPI_Isend/MPI_Irecv, MPI_Waitall, and device unpack; otherwise host staging is used.

Windowed CUDA kernels

Update kernels receive (begin, end) and form absolute_index = begin + tid (tid is the thread index). Global boundary predicates therefore use global indices and keep their one-rank meaning, so an interior rank never takes a branch meant for a physical boundary. Cell and node updates use cw and nw; stencil or interface-scatter passes expand to pw/fw only when required.

The 2D hydro corner-force scatter runs over fw, giving each shared node both adjacent cell contributions without a separate force exchange. The conjugate-gradient (CG) solver of the 2D burn charged-particle diffusion (Burn.scheme="diffusion"; see Nuclear burn) forms its dot products as owned-window partial sums combined with MPI_Allreduce(SUM), and exchanges its search direction in the ghost region at every iteration. The 2D multigroup-diffusion radiation is solved by an operator without rank decomposition, so it is rejected on more than one rank (see features rejected on multiple ranks). On one rank all four windows collapse to [0,n), so a full-range launch is exactly the serial execution.

Reductions and reproducibility

Global energies, timesteps, and solver dot products combine owned-window partial values with standard MPI_Allreduce. This page calls such an operation, which makes one value from the values of all ranks, a reduction. Generic MPI_Allreduce(SUM) does not guarantee bitwise identity across rank counts: the summation order depends on the MPI implementation and the rank layout, so least-significant bits can move when the rank count changes. The repository's docs/NUMERICS.md §12.7.3 accepts this variation, noting that it does not affect the statistical reproducibility of the results.

The 1D stages that must give the same bits at any rank count do not rely on a reduction: each rank gathers the owners' values into the whole line and repeats the same computation (replicated computation). Radiation (FLD, SN), burn, the implicit electron solve and the ion conduction, and the laser ray tracing work this way, so the summation order of MPI_Allreduce(SUM) does not enter their results. The laser deposit is not summed across ranks: every rank holds the same whole-line array and writes the deposit only into the cells it owns. A fixed two-stage reduction by a cooperative grid (cooperative groups) inside a CUDA kernel is deterministic only for a fixed kernel launch configuration (block count); changing the grid size changes the summation order, which counts as a change within the tolerance. These exceptions do not make MPI execution generally bitwise across rank counts.

Features rejected on multiple ranks (deferral guards)

Running an operator whose audit is incomplete on windowed state, without any warning, would miss references to the far region and mismatches in the number of collective calls. An unsupported feature combined with n_ranks>1 (two or more ranks) is therefore made to fail explicitly by the deferral guard. The driver rejects some features at the start of the run, and the operator of the feature rejects others at its first call; namelist validation does not find them (validation does not know the rank count). One step under MPI

  1. Launch owned work. Each operator updates only its owned cell or node range through cw or nw, and forms partial sums from owned entries only.

  2. Extend the ranges that build stencil inputs. Passes that must construct intermediate quantities in the innermost ghost layer expand to pw or fw; far entries remain outside what is read and written.

  3. Refresh the ghost region. After an owner writes and before the first ghost consumer, fields are packed on the device, transferred with non-blocking sends and receives followed by a wait (MPI_Waitall), and unpacked into the two ghost layers. Host staging is used only when GPU-aware MPI is unavailable.

  4. Combine global quantities. Owned partial energies, timestep limits, and solver dot products are combined with the appropriate MPI_Allreduce, normally SUM for additive quantities.

  5. Synchronize LaserMesh. The LaserMesh is the grid used for the laser ray tracing (see Laser). Before tracing, the density, electron temperature, mean ionization, material volume fractions, and node positions are gathered with MPI_Allgatherv over the whole line in 1D and the whole mesh in 2D. In 1D, every rank traces rays through this whole line (replicated computation) and writes the deposit only into the cells it owns. For the 2D mapping onto the LaserMesh, each rank writes its owned cells' values (electron density, electron temperature, mean ionization), centroids, areas, and void flags, and the coordinates of the node columns it owns, into whole-lattice arrays that are zero elsewhere, and one MPI_Allreduce(SUM) collects them on all ranks. Each entry has a single contributing rank, so the sum is the owner's value itself. Every rank maps all LaserMesh nodes from the collected lattice by the same procedure and traces rays through the same field. The deposit is placed directly into the hydro cells that the rays cross, and only the values of the cells a rank owns are kept (the other cells are set to zero).

  6. Check the supported scope. The driver rejects any enabled feature whose CUDA kernels, exchanges, or collective ordering have not been audited for multiple ranks, at the start of the run or at the first call of its operator (features rejected on multiple ranks).

Verification

  • Rank-count comparisons use the one-rank run as reference and assign each deck a comparison tier (bitwise identity, band, or envelope). The 1D tests use bitwise identity, the 2D SN and burn tests use a band (tolerance \(10^{-13}\)), and the 2D LaserMesh test uses an envelope.
  • parallel_halo_exchange_np2 and parallel_halo_exchange_np4 check only the ghost exchange. Each rank writes integer values that contain its rank number into its owned window; after the exchange, the test requires that the two layers outside the owned window equal the owner's values exactly, that everything beyond them keeps its initial value, and that the shared node plane holds the lower-numbered rank's value (owner overwrite), all as exact comparisons of integers. The decompositions tested are the 1D slab, the 2D r-slab, the 2D z-slab, and, with four ranks, a 2×2 split (cells only, including the corner ghosts).
  • In 1D, rank 0 writes the snapshots, checkpoints, and history from its global-size arrays. At the end of every step (and before the step-0 outputs), all ranks gather the fields that each rank updates only on its owned cells and nodes (hydro, the EOS closure, the radiation energy moved with the cells, and node positions and velocities), so the outputs hold the owners' values (2026-09-26; before that date, 1D outputs and checkpoints written with more than one rank held stale values in the other ranks' cells). A radiation-driven capsule deck with burn and ion conduction (FLD, 360 cells, to 6 ns) gives bitwise-equal snapshots at one, two, and four ranks.
  • ctest --test-dir build -L mpi_gate --output-on-failure runs the current thirteen-case MPI battery; the table lists its contents. Of the thirteen tests, eleven (all except the two snapshot tests) compare the owned-window dump of each rank with the one-rank run, and the two snapshot tests compare all numeric datasets of the output files.
