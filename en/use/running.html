Running simulations reference

Starting from a built build/tenryu, this page takes you all the way through: complete a first run, write your own deck, and fix things when they break. TENRYU's input is one Python file (the namelist deck). Python callables are evaluated once at initialization and frozen into tables; Python never runs inside the time loop.

At a glance

  • Four CLI subcommands: run (execute), validate (check without running), verify (registered verification cases), freeze (dump the frozen JSON). Always validate before run — nearly all configuration mistakes are caught before execution.
  • For a first run, execute a template from examples/templates/ as-is; it completes without any editing.
  • tenryu always means the built executable build/tenryu — there is no install step. Invoke it by path from the repository root, or add build/ to PATH.
  • The schema is strict: unknown keys, wrong types, and unsupported combinations stop with an error rather than a warning, and typos get suggestions like did you mean 'kappa_a'?.
  • Re-running into the same output directory does not overwrite; results go to a numbered sibling like _001. If "nothing changed", check the output location first.

Prerequisites

Machine and compiler conditions are on System requirements; producing build/tenryu is covered by Building. Everything below assumes a finished build and a shell at the repository root.

CLI subcommands

CommandInputPurpose
tenryu validate <deck.py>any deckChecks without running (seconds). Beyond schema and combination checks it prints a pre-flight summary — dimension, grid, materials, which physics modules are ON/OFF, output location. Eyeball the summary before running; it is the cheapest debugging there is.
tenryu run <deck.py>any deckThe real run: reads the deck, validates and freezes it, builds mesh/material tables/initial state, then enters the time loop. --output-dir <dir> overrides the output location without editing the deck (new runs only; combining with a restart is a ConfigError).
tenryu verify <name>registered case nameRe-runs analytic, golden, and integrated checks (e.g. sedov, noh, gxii_1d_fld_regression). See Verification & benchmarks.
tenryu freeze <deck.py>any deckWrites out the frozen configuration JSON — for inspecting or diffing effective values without running.

A first run (complete a template)

examples/templates/ ships three runnable skeletons with comments on every block. Start with the lightest one, the radiation slab, unmodified:

# 1. pre-flight check (does not run; takes seconds)
./build/tenryu validate examples/templates/template_1d_slab_radiation.py

# 2. run
./build/tenryu run examples/templates/template_1d_slab_radiation.py

# 3. inspect the results (location set by the deck's Output(directory=...))
ls outputs/template_1d_slab_radiation/results/

If step 3 shows snapshots like <name>_0000.h5 next to <name>_history.h5, the run completed. While running, the console (and log/ under the output directory outputs/<name>/) shows step progress and output events like [output] wrote snapshot (step=…, …). The fastest way to look at the data is the bundled tool:

python3 -m tools.tenryu_plot profile outputs/template_1d_slab_radiation   # spatial profiles
python3 -m tools.tenryu_plot history outputs/template_1d_slab_radiation   # time series
TemplateContentWhat it teaches
template_1d_slab_radiation.pyPlanar 1D, grey FLD, Marshak-driven boundary, hydro OFFThe minimal radiation setup; the validate → run → plot loop.
template_1d_laser_sphere.pySpherical 1D, direct laser drive, two temperatures, conduction ONWriting laser waveforms; multi-physics.
template_1d_indirect_tr.pySpherical 1D, Tr(t) indirect driveThe time-dependent-callable → frozen-table idiom.

The standard first modifications: change the drive temperature or laser power (the callable's return value), double nr and check convergence, and switch to Radiation(mode="sn_transport") to compare with FLD. Copy a template and rename it before editing. The three Studio presets validated through to their physics metrics are on Examples & presets.

Deck anatomy

Main identifies the case and supplies its dimension and stopping conditions. Mesh creates the domain and zoning. Materials registers materials with EOS and opacity models, while Geometry maps initial volume fractions, density, temperature, and velocity onto the mesh. Radiation and Laser select physical operators. Numerics groups dt, hydrodynamics, conduction, ALE, and safety controls. Finally, Output sets file locations and cadence, and Diagnostics chooses quantities accumulated during the run.

The following is a minimal complete 1D spherical deck made only from real keys. It fills the domain with one ideal-gas material and advances Lagrangian hydrodynamics with radiation, laser drive, and conduction disabled. Its values demonstrate the input form; they do not define a physics benchmark.

from tenryu_namelist import *

fuel = Material(
    name="fuel", A=2.0, Z=1.0,
    eos=dict(model="ideal_gas", ideal_gas=dict(gamma=5.0 / 3.0)),
    opacity=dict(model="constant", kappa_a=0.0, kappa_s=0.0,
                 units="cm2_per_g"),
)

Main(name="minimal_1d", dimension="1D_SPH", temperature_model="2T",
     t_end=1.0e-9, max_steps=1000, seed=12345)
Mesh(r_min=0.0, r_max=0.05, nr=64, grid="uniform",
     motion="lagrangian")
Materials(materials=[fuel])
Geometry(
    volfrac=dict(fuel=lambda r_cm: 1.0),
    rho=lambda r_cm: 1.0,
    Te=lambda r_cm: 1.0,
    Ti=lambda r_cm: 1.0,
    velocity=None,
    radiation_field="zero",
)
Radiation(enabled=False)
Laser(enabled=False)
Numerics(
    dt=dict(initial_s=1.0e-12, max_s=1.0e-10, min_s=1.0e-18,
            cfl_hydro=0.3),
    hydro=dict(boundary_1d="free"),
    conduction=dict(enabled=False),
)
Output(directory="outputs/minimal_1d", plot_every=10,
       history_every=1, checkpoint_every=100)
Diagnostics(enabled=True, every=1)

Principles for writing your own decks

  • Units are always cgs + eV. Length cm, time s, density g/cm³, temperature eV. To write in µm, define um = 1.0e-4 yourself and convert. Only keys whose names state a unit (wavelength_nm, …) are exceptions.
  • Spatial profiles and time waveforms are functions. Geometry.rho/Te/Ti/volfrac are vector-evaluated once over cell-center coordinates, laser powers and Marshak temperatures once over time, and frozen into tables. A deck that relies on mutable external state or per-step re-evaluation is incorrect.
  • Unwritten keys take defaults. The canonical defaults are docs/SPECIFICATION.md §9.1. When unsure, leave the key out and confirm effective values in the validate summary and config/*_frozen.json in the output directory.
  • Typos stop the run. Unknown blocks or keys, numbers where strings belong, negative cell counts, and combinations unsupported in the chosen dimension are a ConfigError, never silently ignored. When a "did you mean …?" suggestion appears, apply it.
  • Add physics one piece at a time. The opt-in packages (CBET, hot electrons, SNB, viscosity, burn, …) are contractually inert unless written. Bring a new deck up first on a small mesh with a short t_end, then raise the resolution and output cadence to production values.

What you see while it runs

run first validates and freezes the deck (the same checks as validate), builds the mesh and initial state, and enters the time loop. From there the log carries step progress, and every snapshot/checkpoint write emits a line like [output] wrote snapshot (step=…, …). Logs go both to the console and to outputs/<name>/log/.

When "\(\Delta t\) keeps shrinking and the run crawls", read the limiter name in the log (hydro, conduction, braginskii, …) to identify the limiting kernel, then revisit that physics (floors, zoning). The decision rule and every kernel's formula are collected on Time-step control & CFL.

Output locations

Plots, history, and checkpoints go under Output.directory; outputs/<name> is the standard organization. The directory contents (results/, config/, checkpoints/, log/, run_info.json), file naming, and the complete dataset enumeration are on Outputs & analysis. plot_every, history_every, checkpoint_every are step-count cadences (0 disables); the _s variants (plot_every_s, …) are seconds-based, and both fire under OR logic. To specify cadence in time, always use the _s keys — a classic unit accident otherwise.

Checkpoints and restart

A restarting deck sets Main.restart_from to a checkpoint prefix — e.g. Main(..., restart_from="outputs/minimal_1d/checkpoints/minimal_1d_ckpt_0100"), i.e. the prefix without any rank suffix or .h5. The restart inherits the stored state, time, and time step, and continues the original output layout. If no checkpoint matches the prefix, or the frozen configuration disagrees (dimension, mesh, materials, groups, seed), the run fails before starting.

When it does not work

SymptomCause and fix
ConfigError: ... is not a supported key (did you mean 'X'?)A typo; apply the suggestion.
ConfigError: eos.file is required for model=sesameTable EOS models need their file. Use ideal_gas while learning.
Errors on Radiation.mode="imc_ddmc"The old Monte Carlo transport is retired. Omit the mode (= FLD default) or use sn_transport. The imc=dict(...)/ddmc=dict(...) subblocks are likewise retired-path compatibility keys.
Ran again but results look staleThe output directory collided and results went to a numbered _001 sibling; check the location.
No heating / the wave does not moveCheck the enabled modules in the validate summary first, then the effective boundary/opacity values in config/*_frozen.json.
\(\Delta t\) shrinks foreverIdentify the limiting kernel from the limiter name in the log (Time-step control). Falling below dt.min_s stops FATAL.
CMake / build-stage failuresSee Building and System requirements.

The efficient inspection order is ① the validate summary → ② config/*_frozen.json (effective values) → ③ warnings in log/.
