System requirements reference

TENRYU is a CUDA-only GPU code. This page collects in one place the machine, GPU, compiler, and library requirements for building and running it. The Building page covers the procedure; this page covers the conditions under which that procedure works.

At a glance

  • Required: an NVIDIA GPU plus CUDA Toolkit 12.x (12.0+), a C++20 compiler (GCC 12+ / Clang 15+), CMake 3.27+, Ninja, Python 3.10+ (with development headers), and the Boost headers.
  • By default the build targets the compute capabilities of the local GPUs that nvidia-smi reports at configure time; a host without a visible GPU falls back to 70;80;89;90 (a fatbin: one binary that carries the machine code for the four generations Volta, Ampere, Ada, and Hopper). Continuously exercised hardware: A100 (40/80 GB), RTX 4090, RTX 3090.
  • MPI (Message Passing Interface) and Hypre (a linear-solver library) are optional (default OFF); HDF5 and Python are default ON. The current version has no computation path that uses Hypre, so Hypre is normally not needed. The small test, logging, CLI, and Python-binding dependencies (Catch2, spdlog, CLI11, pybind11) are fetched automatically at configure time if missing — offline machines need them preinstalled. The Boost headers are never fetched automatically and must always be preinstalled.
  • All development and validation experience is on Linux x86_64; other operating systems are untested.

Platform and GPU

The only supported backend is NVIDIA CUDA; other backends, such as HIP (AMD's GPU programming environment), are out of scope by design. Without a GPU the code may build but cannot run. The basic execution shape is one process = one GPU: a single GPU needs no MPI, and multiple GPUs run as one MPI rank (one MPI process) per GPU (see below).

Toolchain and libraries

The canonical minimum versions live in docs/ARCHITECTURE.md §2.2 in the repository (for CMake alone, in the top-level CMakeLists.txt). Requirements fall into three main tiers—required, default-ON (removable but normally used), and optional (default OFF)—plus test, internal, and analysis dependencies.

DependencyMinimumTierRole / caveats
CUDA Toolkit12.0+requirednvcc, runtime, cuSPARSE, cuSOLVER, and cuBLAS. The cuRAND device API (Philox4x32-10) and NVTX (NVIDIA Tools Extension, for profiling annotations) ship with the toolkit and need no extra link libraries.

Boost (Multiprecision headers)none specified (verified with 1.83)requiredOnly boost/multiprecision/cpp_int.hpp is used; no Boost library has to be built, and CMake does not check the version. The remap of 2D ALE (arbitrary Lagrangian–Eulerian) uses it for the exact clipping of polygons, the reference computation of their volumes and moments, and exact sums that do not depend on the summation order, all in arbitrary-precision integers and rationals. Even for 1D-only use, CMake searches for this header at configure time and stops when it is missing; it is never fetched automatically. When the header is not in a standard location, give -DTENRYU_EXACT_GEOMETRY_BOOST_INCLUDE_DIR=<dir>, where <dir>/boost/multiprecision/cpp_int.hpp exists. On Debian/Ubuntu it can be installed with the package libboost-dev.

When ON, CMake requires a Hypre built with CUDA (HYPRE_USING_CUDA defined in HYPRE_config.h).

About networking. Catch2, spdlog, CLI11, and pybind11 are downloaded by CMake's FetchContent at configure time when not found on the system, so the first cmake is easiest with internet access. On offline machines (e.g. compute nodes of a computing center), preinstall them or run the first configure where the network is available. CUDA, the Boost headers, HDF5, Python, MPI, and Hypre are never auto-fetched and must always be preinstalled.

Pre-flight checks

If the following five checks pass, the required conditions are essentially met.

# GPU and driver (CUDA Version must be 12.x or newer)
nvidia-smi

# CUDA compiler (release 12.x)
nvcc --version

# Build tools
cmake --version     # 3.27 or newer
ninja --version

# Python (3.10+, with development headers)
python3 --version
python3 -c "import sysconfig, pathlib; p = pathlib.Path(sysconfig.get_paths()['include'], 'Python.h'); print(p, 'OK' if p.exists() else 'MISSING')"

# Boost headers (when they are in a standard location; otherwise tell CMake where they are)
ls /usr/include/boost/multiprecision/cpp_int.hpp

Once these pass, continue to Building; that page also covers what to do when CMake reports a missing package.
