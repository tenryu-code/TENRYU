Outputs & analysis reference

One TENRYU run produces three kinds of HDF5 — snapshots (spatial fields), a history (scalar time series), and checkpoints (for restart) — plus provenance files (frozen configuration, run info, logs). This page is a complete enumeration of what gets written: file kinds and naming, every snapshot group and dataset, every history channel, the checkpoint additions, and how to read them. The canonical source including dtypes and array shapes is docs/SPECIFICATION.md §7 in the repository (summarized in docs/OUTPUT_SCHEMA.md).

At a glance

  • Three HDF5 kinds: snapshots <name>_NNNN.h5, the history <name>_history.h5 (append-only), and checkpoints <name>_ckpt_NNNN.h5. Cadence fires on step-based (plot_every …) OR seconds-based (plot_every_s …) triggers.
  • Every numeric dataset carries a units attribute. mesh/ and hydro/ dataset names map 1:1 to the internal State field names.
  • Stagnation peaks are short — about 15 ps for the GXII-class laser_capsule preset — so peak values are read from the per-step history (implosion/*), not from snapshots.
  • Re-running into the same output directory does not overwrite: results go to a numbered sibling like _001. If "nothing changed", check the output location first.

Files, naming, cadence

FileNamingCadencePurpose
Snapshot<case>_NNNN.h5 (4-digit zero-padded cycle)every plot_every steps or every plot_every_s seconds (OR logic)Field visualization and post-processing. Physical time in root attribute t.
History<case>_history.h5history_every / history_every_s (OR, appended)Scalar diagnostics time series; extensible datasets appended each output.
Checkpoint<case>_ckpt_NNNN.h5 (per-rank files add _rNNNN)checkpoint_every / checkpoint_every_s (OR)Restart. Only checkpoint_keep_last files are kept; older ones are deleted automatically.

<case> is Main.name, falling back to the namelist file name (without extension). Parallel I/O differs by role: snapshots are one file via parallel HDF5 (MPI-IO, collective writes), the history is written by rank 0 only, and checkpoints are per-rank files. The directory layout:

outputs/<name>/
├── results/                  ← snapshots and history
│   ├── <name>_0000.h5
│   ├── <name>_0001.h5
│   └── <name>_history.h5
├── config/                   ← provenance (frozen config, namelist copy)
│   ├── <name>_frozen.json
│   └── <name>_namelist.py
├── checkpoints/              ← restart
│   └── <name>_ckpt_0100.h5
├── log/                      ← run logs
└── run_info.json             ← run summary (termination state etc.)

If the output directory already exists and collides, nothing is overwritten: results are written to a 3-digit numbered sibling such as outputs/<name>_001/. To redirect output without editing the deck, use tenryu run <deck> --output-dir <dir> (new runs only; combining with a restart is a ConfigError).

Snapshots: every dataset

Root attributes: t (time [s]), cycle, geometry ("1D_SPH"|"2D_RZ"), n_cells, n_nodes, n_groups, n_materials, schema_version. In 1D, arrays are flat and mesh/x_z, v_z are omitted. Group by group ("optional" = written conditionally):

The golden-regression summary metrics quoted on the verification page are time reductions of these series: rho_peak_max = max of implosion/rho_peak, rhoR_max = max of implosion/rho_R, Tc_max = max of implosion/center_temperature, shell_r_min = min of implosion/shell_radius_min.

Warning: cadence can miss the peak

Snapshot cadence is per-deck, but stagnation peaks can be very short — about 15 ps measured (2026-07-31) for the GXII-class laser_capsule preset. When output times straddle the peak, the maximum density among snapshots badly underestimates the true peak. Read sharp peak values and times from the per-step history (implosion/rho_peak) and use snapshots for the spatial structure around the peak.

Checkpoint additions and restart compatibility

Checkpoints store the snapshot content plus the internal state needed to resume.

GroupContent
hydro_flags/hydro_activePer-cell hydro activity mask.
rng/RNG state (rng_counter, global_id).
time_state/t, step, dt, cumulative energy terms, user_seed. The restart Δt comes from here.
output_state/Next scheduled output times (t_next_plot, t_next_history, t_next_checkpoint).
particles/Particle pool of the retired Monte Carlo paths (not applicable to production FLD/SN).

Restart compatibility: matching schema_version reads normally; an older (or missing) version reads with backward-compatible defaults; a newer version is refused. A mismatch in the frozen items (dimension, mesh, materials, group count, seed, group bounds) refuses the restart. How to specify a restart is on the running page.

Provenance: frozen JSON, run_info, logs

config/<name>_frozen.json records the fully resolved configuration, the tables frozen from callables at initialization, and hashes of their sources. It is the primary audit of what the run actually received (rather than what you think you typed); keep it with the deck for reproduction and comparison. run_info.json summarizes the run and log/ holds the run logs. When "did my setting take effect?" arises, read the frozen JSON first, then the warnings in the log.

Reading the data: CLI, bundled tools, Scope

Structure inspection needs only the standard HDF5 tools:

h5ls  outputs/<name>/results/<name>_0010.h5          # group listing
h5dump -H outputs/<name>/results/<name>_history.h5  # header structure

The fastest plots come from the bundled tenryu_plot (tools/), with subcommands including profile (spatial profiles), history (time series), spacetime, summary, compare, and spectrum:

python3 -m tools.tenryu_plot --help                  # list
python3 -m tools.tenryu_plot profile outputs/<name>  # spatial profiles
python3 -m tools.tenryu_plot history outputs/<name>  # time series

For direct reading, h5py is shortest. Every numeric dataset has a units attribute, and array lengths follow the field layout (cells, nodes, cells×materials, cells×groups) — read root attributes, shapes, and units together:

import h5py
f = h5py.File("outputs/<name>/results/<name>_0010.h5")
Te = f["hydro/Te"][:]; r = f["mesh/x_r"][:]
print(f["hydro/Te"].attrs["units"])   # -> "eV"

For interactive exploration and run-to-run comparison, use TENRYU Scope (see Architecture). Find the interesting times and quantities in the viewer, then make the final figures from the frozen configuration and explicit script arguments to combine interactivity with reproducibility.
