Namelist reference reference

This page is an orientation map, not an exhaustive Python-namelist specification. It connects top-level blocks and important sub-blocks to representative keys. The complete key surface — types, units, accepted values, combination rules, and the authoritative default list — lives in the specification shipped with the source: docs/SPECIFICATION.md §6.4 (schema) and §9.1 (defaults) in the TENRYU repository, which is publicly readable alongside the code.

At a glance

  • Blocks from Main through Parallel divide case identity, mesh, materials, initialization, physics, numerics, and output responsibilities.
  • Each nested dict has its own schema. For example, Numerics.dt.max_s and Numerics.hydro.av_C2 belong to different contracts.
  • Unknown keys, wrong types, out-of-range values, and unsupported block combinations are input errors. A typo does not silently fall back to a default.
  • The keys below are entry points, not complete lists. This page's tables deliberately omit defaults; the per-kernel pages list selected defaults, and SPECIFICATION §9.1 is authoritative if they ever disagree.

A deck normally imports tenryu_namelist and calls each top-level constructor once. Create Material(...) objects and register them through Materials(materials=[...]); create LaserBeam(...) objects and pass them through Laser.beams. The “representative keys” column is a search index. Detailed nested schemas and mode-specific exclusions remain in the specification.

Reading key paths

Think in fully qualified paths when similarly named controls appear in several places. Radiation.enabled, Numerics.conduction.enabled, and Burn.enabled are separate switches. Radiation boundary keys are another important example: some belong to the selected solver's mode-specific sub-block, while other drive controls belong to top-level Radiation.boundary. Do not infer nesting from the final key name; consult the matching §6.4 block.

Values use the cgs + eV system: length in cm, time in s, density in g/cm³, and temperatures and photon-group edges in eV. A key that names another unit—such as wavelength_nm or T_floor_keV—uses the suffix as part of its contract. Units, exact types, and dimension-specific restrictions are intentionally omitted from this map and must be checked before entering production values.

Validation and defaults

The parser applies known-key validation at every hierarchy level. It does not discard unknown keys and continue. Wrong types, missing required values, invalid ranges, mutually exclusive modes, and settings unsupported for the selected dimension or MPI rank count raise ConfigError. This contract prevents a configuration typo from appearing later as an unexplained physics result.

Authoritative full reference and defaults

This page is only an orientation map. The authoritative full key reference is docs/SPECIFICATION.md §6.4 in the TENRYU repository (a public document distributed with the source), and the authoritative defaults are in its §9.1. The default values printed in the per-kernel pages of this site are accurate as of the documentation date in the footer; where the site and SPECIFICATION §9.1 ever disagree, §9.1 wins. Consult it when writing a new deck, changing mode, relying on a default, or resolving a validation error.
