1. 概要とワークフロー

TENRYU Studio は、フォームへの入力から右ペインの Python デッキ (namelist) を常時自動生成し、検証 (validate) を経て保存・実行までを行うための GUI です。単位系は cgs + eV で、長さは cm、時間は s、温度は eV、密度は g/cm3、パワーは W を使用します。

ヘッダーには「読込」「保存」「別名保存」、言語切替、実行サーバー選択、validate 実行、実行▶があります。左ナビには「プリセット」「基本設定」「材料」「ジオメトリー」「物理」「駆動」「出力」「実行履歴」「サーバー」が並び、中央に選択中のフォーム、右側に deck プレビューと検証パネルが表示されます。

ヒント: TENRYU-GUI-STATE コメントがあればフォームを完全復元します。コメントのない deck も、作業場所・環境変数・ローカルまたはサーバーの実行先を指定して Python を評価し、取込レポートを表示します。

2. クイックスタート (3 分)

  1. 左ナビの「プリセット」を開き、1D タブを選びます。目的に近いカードの「このプリセットを適用」を押します。
  2. 右ペインの deck プレビューで生成内容を確認します。
  3. 「ファイルへ保存」でデッキを書き出し、./build/tenryu run <deck>.py で実行します。実行サーバーを設定済みなら、ヘッダーの実行▶から投入することもできます。
ヒント: フォームに検証エラーがある間は deck の代わりに赤字のエラー一覧が表示され、修正するとデッキ生成が再開されます。詳しくは §4 と §6 を参照してください。

3. 1D プリセット (検証の run つき)

プリセットの 1D のタブには、基本の 6 つ (空白を含む) と、オプションのカーネルを使う 6 つのプリセットがあります。どのプリセットも RTX 4090 で終了時刻まで計算した条件です (CBET のものは 2026-10-05、ほかは 2026-10-01)。2 倍細かいメッシュの計算とは、CBET のもの以外は終了時刻まで、CBET のものは 0.5 ns まで比べて確かめました。各カードの「検証の run」にその結果を載せています。メッシュはメッシュ推薦スキル (tenryu-mesh-1d) で作りました: レーザー照射のものは推薦メッシュ、輻射温度や圧力で駆動するものは層ごとの指定です (§6)。カードの「物性表が必要」は TMAT-H5 の表を使うもの、「計算が重い」は GPU 1 枚で数時間かかるものです。

4. 基本設定

  • ケース名: 出力ディレクトリ名 outputs/<name> になります。
  • 次元: 本マニュアルでは 1D を使用します。2D RZ モードは本マニュアルの対象外です (別途)。
  • 1D 幾何: 球対称、円筒、平面から選びます。
  • 温度モデル: 通常は 2T を推奨します。1T は放射スラブのような単純問題向けです。
  • 乱数 seed: 確率過程の再現に使う seed です。
  • 最大ステップ数: 計算ステップ数の上限です。
  • 終了時刻 t_end: シミュレーションの物理終了時刻を s で指定します。

5. 材料

  • A/Z: 原子量 A と原子番号 Z を指定します。
  • EOS: ideal_gas では γ を指定し、必要なら cve を上書きします。TMAT テーブルを使う場合はテーブルファイルを指定します。
  • 不透明度: constant では κa、κs [cm²/g] を指定します。テーブル不透明度も選択できます。
  • 参照状態: 物理タブで T_start 未満のセルの扱いを cold_equilibrium にすると現れます。参照密度 ρ0、参照電子温度 Te0、参照イオン温度 Ti0、参照全圧 P0、体積弾性率 K0 を指定します (eos.cold_reference)。モードを選んだ時点で、その材料の最初の領域の密度と温度が入り (P0 = 0)、「初期状態から設定」で入れ直せます。K0 は材料ごとに入力します (文献値の例: 液体 D2 1.2×109 dyn/cm²、ポリスチレン 5.8×1010 dyn/cm²)。
定数不透明度の目安: CH の sub-keV 帯 Planck 平均は数千 cm²/g 級です。旧来デモでよく使われる κ=100 は薄すぎて放射がほぼ素通りし、爆縮系では殻がその場加熱で爆発します。検証済みプリセットが κ=2000 を使うのはこのためです。

6. ジオメトリー: 格子と領域

メッシュの作り方 (1D)

1D の格子は流体とともに動く Lagrange 格子です。「メッシュの作り方」で次の 6 つから選びます。作り方を切り替えても、それまでの作り方の設定は消さずに残します。

作り方 deck に書くもの 使いどころ
一様 nr・grid="uniform" 試しの計算。表面を細かく分ける必要がある計算には向きません。
graded 区間ごとのセル数と grading 以前からの指定。既存の deck との互換のために残しています。
推薦メッシュ zoning_intent と resolution_requirement (apply="enforce" と経験的上限 empirical) レーザー照射の deck。サーバーの推薦ツールが作り、サーバーの tenryu で検証します。
層ごとの指定 explicit_nodes (Studio が計算した節点) 輻射温度や圧力で駆動する deck。推薦の範囲から大きく外れる条件。
節点座標の取り込み explicit_nodes 他のコードのゾーニングや、以前の run の格子をそのまま使う。
宣言型の指定 (zoning_intent) zoning_intent 推薦メッシュの手直し。測度・帯・ピン・重み分布を直接書く。

推薦メッシュ

「推薦メッシュを作る (サーバー)」を押すと、選んだサーバーで TENRYU のメッシュ推薦ツール (tools/assist/assist.py recommend-mesh。Claude Code のスキル tenryu-mesh-1d が使うものと同じ) を実行します。推薦ツールは、フォームの標的とレーザーの条件をサーバーの tenryu に読ませ (validate --mesh-preview)、メッシュの収束を測ったキャンペーンの結果から表面のセルの面密度の上限を決めて zoning_intent を組み、サーバーの tenryu で検証してから返します。検証を通らなかった推薦はフォームに入れません。

  • パネルには、検証の状態、セル数、根拠にした測定、表面のセルの上限と検証での実際の値、注意の印、推薦ツールの警告を表示します。注意の印 extrapolation は、条件が測定の範囲の外にあり、較正済みの先験的な上限を使ったことを示します。このときは収束確認用の組で収束を確かめてください。
  • 推薦は、幾何と計算領域、標的の層 (半径・密度・材料)、レーザーの波長と波形、終了時刻、温度モデル、輻射と熱伝導の設定に対して作ります。推薦の後にこれらを変えると「条件が変わりました」と表示するので、作り直してください。
  • レーザー照射の 1D deck 専用です (ソルバーの分解能要求がレーザーの条件から決まるため)。推薦ツールは表面がそのままの標的を前提にしているので、物質のコロナ層 (ramp) とは併用できません。レーザーの合成コロナ (§8) を使ってください。
  • サーバーには、tenryu のバイナリの上の階層に TENRYU の checkout (tools/assist) と、python3 (3.9 以上) が要ります。
  • 「宣言型の指定で手直しする」を押すと、推薦の zoning_intent を編集できる状態に移ります (手で変えたことをパネルに記録します)。

層ごとの指定

層 (材料の領域、コロナ層、外側の真空) ごとにセル数と並べ方を決めます。並べ方は等幅・等質量・等比の 3 つです。等比のときは、隣のセルとの幅の比・端のセルの幅・隣の層の端のセルと質量をそろえる、のいずれかで比を決め、細かくする側 (外側・内側・両端) を選びます。Studio が節点を計算して explicit_nodes として deck に書くので、表示している格子がそのまま計算に使われます。各層の最小のセル幅と、細かい側の隣接比を表示します。

節点座標の取り込み

節点の座標を貼り付けるか (1 行に 1 つ、またはカンマ・空白区切り。表のときは列を指定し、単位を選ぶ)、ファイル (.txt・.csv・.dat・run の凍結設定 config/<ケース名>_frozen.json) から読み込みます。「サーバーで確かめた格子を使う」は、直前にサーバーで確かめた格子 (推薦メッシュや宣言型の指定からソルバーが作ったもの) を節点の一覧として取り込みます。実行履歴の run を選ぶと、その run の格子 (凍結設定に節点の一覧があればそれ、無ければ run の deck をサーバーで確かめた格子) を取り込みます。取り込むと r_min と r_max を最初と最後の節点に合わせます。

宣言型の指定 (zoning_intent)

ソルバーの宣言型のゾーニングを直接編集します。セル数 n_cells、等分配する測度 measure (幅・面密度・線質量・セル質量)、ゾーニング用の密度の区間、材料の境界のピン、重み分布、局所の細分化、帯 (全測度に対する割合の範囲ごとの、セルの測度の下限と上限)、最小セル幅、隣接比の望ましい値と上限、区間ごとの最小セル数を指定できます。節点はソルバーが計算します。メッシュの診断には、Studio がソルバーと同じ計算で求めた節点の格子を表示し、サーバーで確かめるとソルバーの作った格子に替わります。

分解能要求 (resolution_requirement)

ソルバーは、レーザー照射の deck について、アブレーションの規則と衝撃波の規則からセルの大きさの上限 (分解能要求) を計算します。「書かない」はソルバーの既定 (報告だけ)、「報告だけ」は apply="report"、「満たさなければ止める」は apply="enforce" を書きます。推薦メッシュは enforce と、推薦の根拠にした経験的上限 (empirical) を書きます。

メッシュの診断

格子の性質を図と数で表示します。表示する量はセル幅、面密度 ρΔr、分解能要求の測度 (セル質量 ÷ 表面の参照面積)、隣のセルとの質量比、セルの質量から、横軸は位置 r、表面からの深さ (対数)、セル番号から選べます。図の下には、セル数・最小のセル幅・隣接するセルの質量比の最大・表面のセル・材料の境界での質量比を表示します。

「サーバーで格子と分解能要求を確かめる」は、選んだサーバーで tenryu validate --mesh-preview を実行し、ソルバーが作る格子そのものに、分解能要求の上限 (赤い破線) と上限を超えるセル (赤い点) を重ねて表示します。推薦メッシュと宣言型の指定は節点をソルバーが計算します。このボタンを押す前は、Studio がソルバーのゾーニングと同じ計算で求めた節点を表示し、ソルバーが zoning_intent を拒む場合はソルバーと同じエラーを表示します。分解能要求を enforce にした deck では、ソルバーは要求の上限を zoning_intent に加えてから格子を作るので、その上限が zoning_intent の帯より厳しい所では最終の格子が図と異なります (図の下にその旨を表示します)。フォームを変えると、表示中のサーバーの結果が古いことを示します。

収束確認用の組

表面のセル (と全てのセル) の質量を半分にした deck を作ります。一様と graded はセル数を 2 倍に、層ごとの指定はセル数を 2 倍にして比を平方根に・端のセルの幅を半分に、取り込んだ節点は各セルを体積の等しい 2 つに分け、推薦メッシュと宣言型の指定はセル数を 2 倍にして帯と測度の上限と最小セル幅を半分にします。ケース名と出力先には _fine を付けます。元の deck と並べて流し、観測量 (アブレーション圧・アブレートした質量・吸収したエネルギー・衝撃波が後面に届く時刻・停滞の時刻など) が変わらないことを確かめます。推薦が測定の範囲外のとき (extrapolation) と、層ごとの指定・取り込みで作った格子では、本番の前に必要です。「細かい組を保存」「細かい組を実行」「細かい組をフォームに開く」から使います。

領域

内側から順に材料領域を積みます。各領域には材料、外半径 rOuter、密度、初期電子温度 Te、初期イオン温度 Ti を指定します。既定では、最終領域の rOuter は r_max と一致している必要があります。

外側真空 (VOID)

「外側真空」を ON にすると、最終領域の外側が VOID 材料でマスクされます。このとき rOuter < r_max が必要です。伝導・放射は VOID を素通りしない扱いになり、床密度で真空域を充填することによる数値病理を避けられます。

プリプラズマ・コロナ ramp

外側真空が ON のとき、コロナ ramp をさらに有効化できます。最終領域表面から指数減衰する低密度コロナを、スケール長 L、範囲、ρ0、床密度で指定します。

重要: レーザーの deck には、レーザーの合成コロナ (§8。レーザーのプリセットはこれを使います) か物質のコロナ ramp のどちらかが必要です。どちらも無いと、冷たい固体の端で光線が臨界面で反射し、吸収が約 0.04% まで落ちて何も起きません。逆制動放射の光路がないためです。フォームはこのとき警告を表示します。ramp の既定値 (L=2 µm / 範囲 10 µm / ρ0=0.05 g/cm³ / 床 3×10−4 g/cm³) は以前の GXII 検証構成です。推薦メッシュは ramp と併用できません。

7. 物理

輻射輸送

輻射輸送を有効化し、ソルバーに FLD (flux-limited diffusion、流束制限拡散) を選びます。群数と群境界 [eV] を指定し、1 群なら灰色近似になります。外側境界は真空または Marshak です。Marshak 温度は定数 Tr、または駆動タブの間接照射と連動する折れ線 Tr(t) で与えられます。

電子熱伝導

電子熱伝導を有効にすると、非局所電子熱輸送モデルを選択できます。「なし」は局所 Spitzer–Härm (SH)、「SNB」は非局所モデルです。モデル選択の下にある flux limiter の係数 f_lim は、モデル切替時に SH → 0.06 (較正済みリミッタ)、SNB → 0.5 (安全キャップ) へ自動設定されます。SNB 自身が非局所抑制を担うため、小さい f のままでは SNB の物理を覆い隠します。

SNB の既定値は、エネルギー群数 24、Emax/(kBTe)=20、群 mfp 変種 geometric_r2 (Sherlock 2017)、電場補正「なし」、Picard 反復上限 8、rtol=0.01 です。r=2 の較正には電場補正が織り込み済みなので、local と併用すると二重計上になります。

熱伝導の解法は、STS (陽的な超時間刻み。ソルバーの既定) と陰的 (1D のみ) から選びます。陰的は熱伝導による時間刻みの制約がなく、例題集のレーザー照射の deck と多くのプリセットが使います。SNB の非局所モデルは STS でしか解けないため、SNB と陰的を組み合わせるとフォームのエラーになります。

  • イオン熱伝導: Braginskii のイオン熱伝導を電子の熱伝導の後に解きます（1D・2T のみ。2D や 1T ではフォームのエラー）。有効にすると、イオン熱流束の制限係数 ion_f_lim（既定 1 = イオンの自由流束）を設定できます。
  • 流体: 有効化、外側境界 (free / reflect / pressure)、流体開始温度 T_start [eV] (セルの電子温度がこの値に達するまで流体計算をしない。0 = 常時有効) を設定します。
  • T_start 未満のセルの扱い: passive_fill (既定。圧力を持たず隣接セルに追従)、rigid_wall (剛体壁として体積とエネルギーを保持、1D 専用)、cold_equilibrium (1D 専用) から選びます。cold_equilibrium では流体計算を全セルで行い、電子温度が T_start 以下のときだけ EOS を補正して、各材料の参照状態を全圧 P0・体積弾性率 K0 の力学平衡に置きます (T_start を超えると元の表に戻ります)。全材料の TMAT EOS と 2T が必要で、選ぶと電子・イオン交換の比熱が table になり、材料タブに参照状態の欄が現れます。遷移開始比・密度範囲・逆変換の反復上限は「詳細」で変えられます。
  • 電子・イオン交換の比熱: ideal_gas (既定) または table (EOS 表の比熱、1D 専用)。
  • プラズマ粘性: 既定は OFF です。

8. 駆動

駆動方式は「なし」「レーザー直接照射」「輻射温度 Tr(t) (間接照射)」「外部圧力 Pext(t)」から選びます。

レーザー直接照射

波長、レイトレース、波形、パワー、パルス長を設定します。1D では単一参照ビームの光学のみを指定し、方向・本数・配分は意味を持たないため表示されません。波形は矩形 (rise/fall 付き)、ガウス、折れ線テーブルから選べます。

「合成コロナ (ghost corona) を使う」を ON にすると、裸の固体の表面の外に、レーザー格子の上だけに置く希薄なコロナを作り、パルスの立ち上がりから吸収させます (NUMERICS §5.7.5)。物質のコロナ ramp の代わりに使うもので、レーザーのプリセットはすべてこれを使います。既定値 (ゴーストセル 12、密度比 0.03〜0.99、電子温度の下限 50 eV、Z̄ 1〜4、受け渡し 6 セル・減衰長 2、ブローオフへの遷移モデルあり、レーザー格子の細かさ mesh_factor 0.1、レーザー格子の外端の密度比 0.001) は、例題集と、推薦メッシュの根拠になった収束キャンペーンの設定です。「堆積の平滑化」は、レーザーの付与を流体のセルへ渡すときに隣のセルとの間で行う、質量で重みを付けた保存的な平滑化の回数と 1 回あたりの重みです。プリセットは 3 回・0.25 を使います (0 回で無効。ソルバーの既定)。

ビーム光学

f 値、スポット w0、スーパーガウス次数を設定します。GXII 検証値は f/3、w0=200 µm、m=4 です。

CBET

CBET を有効化すると、ポート配置プリセット (GXII 12 / OMEGA 60 / NIF 192 の理想化配置) と Δλ デチューニングなどが表示されます。多ビーム間エネルギー交換を、単一参照トレースの位相空間再構成で計算する 1D 専用実装です。

ホット電子

η(t) モデルなどを使って、高速電子の生成・輸送・沈着を付加します。

間接照射 Tr(t)

駆動方式で「輻射温度 Tr(t)」を選ぶと、Marshak Tr(t) の波形エディタが使えます。検証済みの波形例は §3 の間接照射プリセットを参照してください。

外部圧力

1D 境界に対する圧力駆動 Pext(t) を指定します。

9. 出力

  • 出力ディレクトリ: 空欄なら outputs/<ケース名> です。
  • スナップショット間隔: plot_every_s で指定します。
  • 履歴: 時系列の診断量を保存します。
  • チェックポイント: 再開用データの出力を設定します。間隔を空欄にすると途中のチェックポイントは書きません。
  • 終了時にチェックポイントを書く: run が終わった時点のチェックポイントを残します (Output.write_final_checkpoint、既定で ON)。実行履歴の「続きから計算」は、これか途中のチェックポイントのどれかが無いと使えません。2026-09-30 より前の tenryu はこのキーを知らないので、そのようなバイナリで実行するときは外してください。
重要: スナップショットは既定で 50 ps 間隔です。爆縮の停滞ピークは約 15 ps 程度しかなく、スナップショットの ρ 最大値はピークを過小評価しえます。ピーク値は per-step 履歴の implosion/rho_peak で読んでください。

10. デッキの確認・保存・実行

右ペインには常に最新のデッキが表示されます。「コピー」「ファイルへ保存」「読み込み」を使ってデッキを扱えます。

検証パネルの「validate 実行」は、選択サーバー上で dry-run 検証を行います。実行▶は選択サーバーへジョブを投入し、進行状況は「実行履歴」タブで追跡できます。サーバー未設定でも、デッキを保存して手元で次のように実行できます。

./build/tenryu run deck.py

続きから計算 (run の延長)

実行履歴の終わった run にある「続きから計算…」を押すと、終了時刻と最大ステップ数の欄が開きます。延ばしたい値を入れて「続きから計算を開始」を押すと、サーバー上の同じ run ディレクトリで、同じ deck.py を変えずに、最新のチェックポイントから再開します。変えた値は tenryu run の --t-end・--max-steps として渡され、値を変えなければそのまま再開します。

  • 続きの出力は同じ run ディレクトリの outputs/<ケース名>_001 (2 回目は _002) に書かれます。結果の履歴のグラフは元の run と続きをつないで表示し、続きがチェックポイントより後の区間を計算し直した場合は、その区間を続きの値で表示します。プロファイルのスナップショットは、元の run のものに続けて続きのものを並べます。「Scope で開く」で開く TENRYU Scope は、全スナップショットの先読みが終わった時点で、続きが計算し直した区間の元の run のスナップショットを一覧から除き、時空図も続きの結果で作ります。
  • 最新のチェックポイントは、いちばん新しい出力ディレクトリの最後のものです。終わった時点から続けるには、出力タブの「終了時にチェックポイントを書く」を ON にして実行しておきます。途中のチェックポイントしか無い run は、そこから計算し直して延ばします。
  • 終了時刻・最大ステップ数は、現在の時刻・ステップ数より大きくしてください。LaserBeam.energy_J を使うデッキでは、レーザーの出力の正規化は元のデッキの終了時刻までの区間のままなので、パルスがその後も続くと延ばした区間の分だけエネルギーが追加で入ります (ログの WARNING に量が出ます)。
  • 値を変えた延長には、2026-09-30 以降の tenryu (--t-end・--max-steps に対応したもの) がサーバーに必要です。
ヒント: 保存後に手で編集した Python を取り込むには TENRYU-GUI-STATE コメントを削除します。残っている場合はヘッダのフォーム状態を優先します。ファイル読込と貼付けのどちらでも、評価前に作業ディレクトリー、環境変数（1行に KEY=VALUE）、ローカルの python3 または選択中のサーバーを指定できます。作業場所には deck を実行するディレクトリーを指定してください。「参照…」でサーバー上を移動し、「このフォルダーを選択」で設定できます。作業ディレクトリーを空のまま読み込むと、Studio はサーバー上の同名 deck を探し、その場所と親フォルダーを順に試して最初に成功した場所を採用します（⌘O では設定画面の前に自動で試し、失敗時は試した場所を表示）。サーバーの既定は一時転送先で、このまま失敗した場合は専用の案内を表示します。deck が読む環境変数名を文字列から検出して表示し、ソース変更時にも不足する NAME= 行を追加します。空値は送信せず、継承した環境変数や deck の既定値を使います。ファイル取込に成功すると、実行先・作業場所・環境変数欄をファイルパス別に直近50件までアプリ設定へ保存し、次回は実行先の既定値より優先して復元します。設定はセッション中にも保持し、取込レポートと保存ヘッダに記録します。環境変数の値はヘッダとアプリ設定に平文で保存されます。ソースと関数を子プロセスで複数回評価します（各45秒でタイムアウト）。サーバーでは同梱ハーネス、要求 JSON、deck をプロファイルの実行ディレクトリー配下の一時ディレクトリーに転送し、終了後に削除します。依存ファイルはそのサーバーに必要です。信頼できるコードを取り込んでください。レポートには対応付けた値、標本点で検証した関数、元の Python で保持する設定、追加しない既定値を表示します。フォームの値は取込時に固定され、元ソースで保持する設定は solver 実行時の作業場所と環境に従います。再実行ヘルパーはこれらを変更せず、取込時の環境変数指定も solver には適用しません。保持対象と衝突するフォーム編集はエラーになります。通常のローカル deck はサーバーやミラー不要ですが、mesh-planner の import にはローカルのミラーやサーバーの checkout が必要になる場合があります。__file__ や元ファイル付近のモジュールに依存する場合は、任意の元ファイルパス欄を指定してください。保存後に移動する場合は参照データやモジュールも移してください。

11. アシスタント (実験的)

左ナビの「アシスタント」ビューは、LLM による 1D デッキ生成と決定論的な実行診断を提供します。既定では LLM 機能は無効で、環境変数 TENRYU_ASSIST_DISABLE=1 が常に優先される kill switch です。

準備

  • Mac 側には python3（Xcode コマンドラインツール付属）と、自分でログインした Claude Code か Codex CLI が必要です。
  • Mac に TENRYU を置く必要はありません。「文書とソースの取得元」でサーバープロファイルを選び「サーバーから同期」を押すと、サーバーのチェックアウトから文書・例題・ソースがアプリの設定フォルダに取り寄せられます（未同期なら最初の質問やデッキ生成で自動同期）。アシスタント本体（tools/assist）はアプリに同梱されているので、サーバー側チェックアウトには docs/ と src/ があれば十分です。開発者はローカルのチェックアウトを指定して代わりに使えます。
  • 設定欄の「LLM 設定」でプロバイダ（Claude Code / Codex CLI の雛形）とモデル、役割の割当を選び「保存」すると、アプリの設定フォルダ（macOS では ~/Library/Application Support/jp.osaka-u.ile.tenryu-studio/assistant.toml）に書き出され、状態確認が再実行されます。
  • Studio が使う設定はアプリの設定フォルダの assistant.toml だけです（未作成なら LLM 機能は無効の既定のまま）。CLI 版 (tools/assist) は ./assistant.toml や ~/.tenryu/assistant.toml も探します（雛形: tools/assist/assistant.example.toml）。プロバイダ CLI (codex / claude) はローカルマシンで認証済みであることが前提です。
  • デッキ検証は現在選択中のサーバープロファイルのバイナリで行われます (ssh プロファイルでは tools/assist/tenryu_remote.sh 経由)。ポート・鍵・ホストキー方針はプロファイル設定から自動で引き継がれます。

質問

「質問」欄に TENRYU についての質問を入力して送信すると、ローカルチェックアウトで tools/assist/assist.py ask が実行され、question_answering 役割に設定したプロバイダ（読み取り専用の CLI）が文書とソースを探索して回答します。回答末尾の根拠（path:line）と namelist キーは自動で実在を検査され、確認できなかった項目が表示されます。同じ会話で続けて質問すると前の往復が引き継がれます。作業ディレクトリはアプリの設定フォルダの ask/<stamp>/ です。ヘッダーの「質問チャット」ボタン（⌘J / Ctrl+J）で右側にチャット欄が開き、どの画面からでも質問できる。Enter で送信、Shift+Enter で改行。

デッキ生成

仕様を自然言語で書いて「生成」を押すと、生成 → サーバーでの validate/freeze → lint フィードバックの反復ループが走ります (最大反復 1–10)。モデルが不明点を推測せず質問してきた場合 (UNCERTAIN)、回答欄で答えて再生成できます。受理されたデッキはその場で検証・保存・実行でき、実行は通常の実行履歴に入ります。全 LLM 呼び出しはアプリの設定フォルダの作業ディレクトリ generate/<stamp>/ にある journal.jsonl に記録されます。

Lint と診断

  • 検証パネルの「詳細 Lint」は、現在のフォームデッキに対して solver の validate/freeze に加え、メッシュ・ゾーニング系の lint (節点単調性・隣接幅比・autozone 質量比・intent ピン検査) を実行します。
  • 実行履歴の終了 run には「診断 (アシスタント)」があり、ダイジェスト (履歴系列の縮約と派生指標)・ゾーニング診断 (アブレート帯の質量形 lint)・ゾーニング昇格案を表示します。サーバー側に python3 (ダイジェストには h5py) と tools/assist を含むチェックアウトが必要です。
